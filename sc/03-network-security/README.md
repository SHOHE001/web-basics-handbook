## 本文

### 1. 境界防御の機器

| 機器 | 見るもの | 止められる例 | 止められない例 |
|---|---|---|---|
| **ファイアウォール** | IP アドレス・ポート・通信の状態 | 許可していないポートへの接続 | 許可したポート（443 など）の上の攻撃 |
| **IDS / IPS** | 通信の中身を、既知の攻撃のパターン（シグネチャ）や普段との違い（アノマリ）と照合 | 既知の脆弱性を突く通信 | 暗号化された通信の中身（復号しない限り）、未知の攻撃 |
| **WAF** | HTTP の中身 | SQL インジェクション・XSS のパターン | アプリの仕様の穴（他人のデータを ID の書き換えで見られる、など） |
| **プロキシ** | 接続先の URL・カテゴリ | 業務に不要なサイトへの接続 | 許可したサイトを悪用した通信 |

<mark>**どの機器にも「見えないもの」があるので、1 つに頼らず重ねて防ぐ（多層防御）**</mark> のが原則です。

**誤検知と見逃し**: IDS が正常な通信を攻撃と判定するのが **フォールスポジティブ**（誤検知）、攻撃を見逃すのが **フォールスネガティブ** です。IPS で誤検知が起きると正常な業務の通信が止まるので、導入の初めは検知だけ（IDS として動かす）にして、ルールを調整してから遮断に切り替える運用がよくとられます。

### 2. DNS のセキュリティ

- **DNS キャッシュポイズニング**: リゾルバ（キャッシュサーバ）に偽の応答を覚えさせ、利用者を偽のサーバに誘導する。問い合わせの ID や送信元ポートを推測して、正規の応答より先に偽の応答を送り込む手口がある
- **対策**: 送信元ポートをランダムにする、**DNSSEC**（応答に電子署名を付けて、受け取った側が正しさを検証する）を使う
- **オープンリゾルバ**: 誰からの問い合わせにも答えてしまうキャッシュサーバ。小さな問い合わせで大きな応答を返させ、送信元を偽って第三者に送りつける **DNS リフレクション攻撃**（DDoS の一種）の踏み台にされる。社内向けのキャッシュサーバは、社内からの問い合わせだけに答えるよう制限する
- **DNS over HTTPS / TLS**: 問い合わせ自体を暗号化して盗み見を防ぐ。一方で、組織が DNS の通信を監視しにくくなる、という面もある

### 3. メールのセキュリティの深掘り

AP Chapter 4 の SPF・DKIM・DMARC を、判定の流れで整理します。

1. 受信サーバは、メールを送ってきたサーバの IP アドレスが、**エンベロープの送信者**（配送上の差出人）のドメインの SPF に載っているかを確かめる
2. メールの **DKIM 署名** を、署名したドメインの公開鍵で検証する
3. **DMARC**: SPF か DKIM のどちらかが成功し、かつ、そのドメインが **ヘッダの From**（利用者に見える差出人）のドメインと一致（アラインメント）しているかを確かめる
4. 一致しなければ、From のドメインの DMARC で宣言された方針（`none`・`quarantine`・`reject`）に従って扱う。集計の報告（rua）を送信者側に返すこともできる

> [!CAUTION]
> <mark>**メールを転送すると SPF は失敗しやすい**</mark>（転送サーバの IP アドレスは、元の送信ドメインの SPF に載っていないため）。DKIM は本文とヘッダが変わらなければ転送後も成功するので、DMARC を `reject` にする前に DKIM を整えておく。「DMARC を厳しくしたら正規のメールまで届かなくなった」原因として、この組合せが問われる。

ほかに、メールサーバ間の通信を暗号化する **STARTTLS**、それを強制する **MTA-STS** があります。

### 4. VPN とリモートアクセス

| 方式 | 特徴 |
|---|---|
| **IPsec** | IP の層で暗号化する。拠点間の接続に向く。鍵交換は IKE。通信全体を包む **トンネルモード** と、中身だけを守る **トランスポートモード** がある |
| **TLS-VPN（SSL-VPN）** | TLS を使う。ブラウザや専用アプリから接続でき、在宅勤務の接続に向く |

**VPN 機器の脆弱性**: 外から到達できる VPN 機器は攻撃者に常に探されていて、修正プログラムの公開から間もなく悪用が始まる例が多くあります。ランサムウェアの侵入口として VPN 機器が使われた事例は、IPA や警察庁の注意喚起でたびたび取り上げられています。対策は、修正プログラムの速やかな適用、多要素認証、接続ログの監視です。

### 5. ゼロトラスト

「社内ネットワークの中は安全」という前提（境界型防御）を捨て、<mark>**すべてのアクセスを、利用者・端末・状況に基づいて毎回確かめてから許可する**</mark> 考え方です。在宅勤務やクラウドの利用で、守るべきものが社内ネットワークの外に広がったことが背景にあります。

- **ID を中心にした認証**: シングルサインオンと多要素認証を、すべてのサービスの入口にする
- **端末の状態の確認**: OS が最新か、EDR が動いているかを確かめてからアクセスを許可する
- **最小権限**: 必要なものにだけ、必要な間だけアクセスを許す
- **マイクロセグメンテーション**: ネットワークを細かく区切り、1 台が侵入されても横に広がりにくくする
- **SASE**: ネットワークの機能（VPN の代わりの接続、プロキシ、ファイアウォール）とセキュリティの機能を、クラウドのサービスとしてまとめて提供する考え方

### 6. 無線 LAN のセキュリティ

- **WPA3**: 個人向け（Personal）は、パスワードを推測する攻撃に強い鍵交換（SAE）を使う。組織向け（Enterprise）は IEEE 802.1X で利用者ごとに認証する
- **偽のアクセスポイント**（悪魔の双子）: 正規と同じ名前（SSID）の偽のアクセスポイントを立てて、つないできた端末の通信を盗み見る。対策は、802.1X でサーバの証明書を端末側が検証すること、つないだ後も TLS で守られた通信を使うこと
- **MAC アドレスによる制限の限界**: MAC アドレスは簡単に偽装でき、最近のスマホは接続先ごとにランダムな MAC アドレスを使う（Web 編 Ch2）。認証の代わりにはならない

## 手を動かすパート

DNSSEC で署名されているドメインかどうかは、DNS の応答で確かめられます（Linux / macOS の `dig` の例）。

```bash
# 応答のフラグに ad（認証済み）が付くかを見る。DNSSEC を検証するリゾルバを使う
dig +dnssec www.jprs.co.jp @1.1.1.1 | grep -E "flags|RRSIG"
```

また、自分のメールアドレスに届いたメールの「ヘッダを表示」（Gmail なら「メッセージのソースを表示」）で、`Authentication-Results:` の行に `spf=pass`・`dkim=pass`・`dmarc=pass` が並んでいるのを確かめてみてください。

## つまずきポイント

> [!CAUTION]
> ネットワークセキュリティは **「その対策で、この攻撃が本当に止まるか」** を経路に沿って確かめる問題が多い。機器の名前を書くだけでは点にならない。

- <mark>**各機器の「見えないもの」**</mark>: 許可したポートの上の攻撃、暗号化された中身、アプリの仕様の穴
- <mark>**誤検知（フォールスポジティブ）と見逃し（フォールスネガティブ）**</mark>: IPS の誤検知は業務を止める
- **転送で SPF が失敗する**: DMARC を厳しくする前に DKIM
- **オープンリゾルバは DDoS の踏み台**: 問い合わせ元を制限する
- **MAC アドレス制限は認証ではない**: 偽装できる

## 重要な単語まとめ

| 用語 | 一言で言うと | 身近な実例 |
|---|---|---|
| **多層防御** | 性質の違う対策を重ねる | ファイアウォール ＋ WAF ＋ EDR |
| **シグネチャ型 / アノマリ型** | 既知のパターンと照合 / 普段との違いで検知 | IDS の検知方式 |
| **フォールスポジティブ / ネガティブ** | 誤検知 / 見逃し | 正常な通信が止まる |
| **DNS キャッシュポイズニング / DNSSEC** | 偽の応答を覚えさせる / 応答に署名して検証 | 偽サイトへの誘導の防止 |
| **オープンリゾルバ** | 誰にでも答える DNS サーバ | DNS リフレクション攻撃の踏み台 |
| **エンベロープの送信者 / ヘッダの From** | 配送上の差出人 / 利用者に見える差出人 | DMARC のアラインメント |
| **MTA-STS** | メールサーバ間の暗号化を強制 | STARTTLS の格下げ防止 |
| **IPsec / TLS-VPN** | IP 層の VPN / TLS の VPN | 拠点間 / 在宅勤務 |
| **ゼロトラスト** | すべてのアクセスを毎回確かめる | 社外からの業務クラウド利用 |
| **マイクロセグメンテーション** | ネットワークを細かく区切る | 感染の横展開を防ぐ |
| **SASE** | ネットワークとセキュリティをクラウドで提供 | VPN の置き換え |
| **悪魔の双子** | 正規と同じ名前の偽アクセスポイント | 駅やカフェの偽 Wi-Fi |
