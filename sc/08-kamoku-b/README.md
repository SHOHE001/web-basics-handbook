## 本文

### 1. 形式と時間配分

| 項目 | 内容 |
|---|---|
| 時間 | 150 分 |
| 解答する問題 | 4 問から 2 問を選ぶ |
| 1 問あたり | 70 分前後（問題を選ぶ時間を除く） |
| 合格基準 | 100 点満点中 60 点以上（科目 A-1・A-2 も基準に届いていることが前提） |

1 問あたりの問題文は AP の科目 B よりはるかに長く、ある組織の状況やシステム構成、起きた出来事、対応の経過が図表とともに詳しく書かれています。

### 2. AP との違い

| | AP の科目 B 問 1 | SC の科目 B |
|---|---|---|
| 問題文 | 数ページ | その数倍。ネットワーク構成図、ログ、プログラムの一部、設定ファイルなどが並ぶ |
| 問われる深さ | 対策の種類を答える | 「なぜその対策で防げるのか」「その対策で防げないものは何か」まで、仕組みに沿って説明する |
| 題材 | セキュリティ全般の基本 | ネットワーク・Web・クラウド・開発・インシデント対応に関する具体的な技術の詳細 |

<mark>**SC で点が伸びない典型は、「多要素認証を導入する」「WAF を入れる」のように対策の名前だけを書いてしまうことです**</mark>。本文の状況において、その対策が攻撃のどの段階をどのように止めるのかを、本文にある機器名・通信・設定の言葉を使って書く必要があります。

### 3. よく出る題材

| 題材 | 問われやすいこと | 復習する章 |
|---|---|---|
| **Web アプリの脆弱性** | 脆弱なコードの指摘、攻撃の文字列、修正方法 | SC Ch4、Web 編 Ch6 |
| **認証・認可の連携** | OAuth / OpenID Connect の流れにおける不備の箇所、トークンの扱い | SC Ch2 |
| **メールのセキュリティ** | SPF・DKIM・DMARC の判定結果、なりすましの成否 | SC Ch3 |
| **標的型攻撃・ランサムウェア** | ログからの侵入経路の特定、横展開の手口、対策 | SC Ch5 |
| **インシデント対応** | 対応の順番、証拠の保全、関係者への報告 | SC Ch6 |
| **クラウド・開発** | 設定の不備、権限の範囲、サプライチェーンのリスク | SC Ch7 |
| **ネットワークの設計** | ファイアウォールのルール、DNS、VPN、ゼロトラストへの移行 | SC Ch3、AP Ch7 |

### 4. 長い事例文の読み方

> [!CAUTION]
> <mark>**本文の図表（構成図・ログ・ルール表）と本文の説明は、必ず突き合わせながら読む**</mark>。SC の問題では、図表の 1 行（例えばファイアウォールの許可ルールの 1 つや、ログの 1 行の時刻）に、設問の答えの鍵が置かれていることが多い。本文だけを読んで図表を読み流すと、根拠を見落とす。

読み方の手順（AP Chapter 3 の手順に上乗せ）:

1. **設問を先に読み、答えの種類を把握する**（字句・選択・記述・数値）
2. **構成図に、本文に出てきた機器の役割を書き込む**（どこが DMZ か、どこからどこへの通信が許可されているか）
3. **ログや時系列の表は、時刻順に並べ直して追う**（SC Ch5）
4. **「〜としている」「〜を許可している」という現状の記述に印を付ける**。設問の「問題点」は、たいていこの現状のどれかにある
5. **答えを書く前に、本文と図表の両方で根拠を確かめる**

### 5. 専門家としての答え方

- **主語と対象を具体的に**: 「サーバの設定を変更する」ではなく、「メール中継サーバで、社外から社外への中継を拒否するよう設定する」
- **仕組みに沿って理由を書く**: 「DMARC を設定するから」ではなく、「From のドメインと SPF・DKIM の認証ドメインが一致しないメールを、受信側で拒否させられるから」
- **限界も書けるように**: 設問で「この対策で防げない攻撃は何か」と聞かれることがある。各対策の「見えないもの」（SC Ch3）を思い出す
- **字数は上限の 7〜9 割**（AP Chapter 3 と同じ）
- **本文の用語を使う**: 本文が「業務 PC」と呼んでいるものを「クライアント端末」と言い換えない

### 6. 科目 A-1・A-2 の対策

- **A-1**（30 問）: 高度試験と共通で、AP の科目 A に近い幅広い知識。AP 合格から 2 年以内なら免除（[SC 編の概要](../README.md)）
- **A-2**（25 問）: セキュリティとネットワークを中心とした専門知識。過去問の使い回しが多いので、過去問演習で用語を固めるのが最も効率的
- **注意**: A-1・A-2 が基準点に届かないと、科目 B は採点されない。科目 B の勉強に偏りすぎて A-2 を落とすのは、もったいない落ち方である

## 手を動かすパート

この編の総まとめとして、Web 編で作ったアプリを題材に、自分で「事例問題」を作ってみてください。

1. Web 編 Ch5 の TODO アプリ（`chapters/05-web-app/code/`）の構成図を描く（ブラウザ・HTML 配信サーバ・API・データ）
2. SC Ch7 の脅威モデリングの手順で、境界ごとの脅威を挙げる
3. 「このアプリを社外に公開するとしたら、どんな問題が起きるか。30 字以内で述べよ」という設問を自分で作り、本文（自分で描いた構成図）を根拠に答える

出題者の立場で問題を作ると、「どこに根拠を置くか」「どんな答えなら点をあげられるか」が見えてきます。

## つまずきポイント

> [!CAUTION]
> SC の科目 B は、知識があっても **書き方** で点を落とす。書き終えたら、次の 5 つを見直す。

- <mark>**対策の名前だけで終わっていないか**</mark>: どこで、どう効くのかまで書く
- <mark>**図表の根拠を確かめたか**</mark>: ルール表・ログの 1 行に鍵がある
- <mark>**本文の用語で書いているか**</mark>: 言い換えると根拠が伝わりにくい
- **「防げないもの」を聞かれていないか**: 対策の限界を答える設問もある
- **A-2 の基準点**: 科目 B に偏らない

## 重要な単語まとめ

| 用語 | 一言で言うと | 身近な実例 |
|---|---|---|
| **科目 B（SC）** | 4 問から 2 問を選ぶ記述式。150 分 | 1 問あたり 70 分前後 |
| **事例問題** | 組織の状況と出来事から答える長文の問題 | 構成図・ログ・設定ファイル付き |
| **根拠の突き合わせ** | 本文と図表の両方で答えを確かめること | ルール表の 1 行が鍵 |
| **対策の限界** | その対策では防げないもの | WAF ではアプリの仕様の穴は防げない |
| **科目 A-1 / A-2** | 共通の幅広い知識 / セキュリティの専門知識 | AP 合格で A-1 免除 |
| **多段階の採点** | A が基準未満なら B は採点されない仕組み | A-2 の取りこぼしに注意 |
