## 本文

### 1. セキュリティは経営の課題

セキュリティの事故は、システムの問題にとどまらず、事業の停止・賠償・信用の失墜につながります。そのため、<mark>**セキュリティ対策の最終的な責任は経営者にある**</mark> という考え方が基本になっています。

- **セキュリティガバナンス**: 経営者が方針を示し、対策に資源（予算・人）を割り当て、実施状況を監視する仕組み
- **サイバーセキュリティ経営ガイドライン**（経済産業省・IPA）: 経営者が認識すべきことと、担当幹部（CISO など）に指示すべき事項をまとめたもの。取引先や委託先を含めた **サプライチェーン全体** の対策も求めている

### 2. NIST サイバーセキュリティフレームワーク（CSF）

米国の NIST が作った、組織のセキュリティ対策を整理するための枠組みです。2024 年の 2.0 版で、次の 6 つの機能に整理されました。

| 機能 | 中身 |
|---|---|
| **統治**（Govern） | 方針・役割・責任を決め、経営として管理する（2.0 で追加） |
| **識別**（Identify） | 守るべき資産とリスクを把握する |
| **防御**（Protect） | アクセス制御・教育・データ保護などで被害を防ぐ |
| **検知**（Detect） | 攻撃や異常に気付く |
| **対応**（Respond） | 起きた事態に対処する |
| **復旧**（Recover） | 元の状態に戻す |

「防御」だけでなく「検知・対応・復旧」まで含めて備える、という考え方が SC の科目 B の土台です。

### 3. リスクアセスメント

#### 進め方

1. **リスクの特定**: 守るべき情報資産、それに対する脅威、つけ込まれる脆弱性を洗い出す
2. **リスクの分析**: 起きる可能性と、起きたときの影響の大きさを見積もる
3. **リスクの評価**: 分析の結果を、組織が受け入れられる基準（リスク受容基準）と比べて、対応の優先順位を決める

そのあと、回避・低減・移転・受容のどれで対応するかを決めます（FE Chapter 8）。対応したあとに残るリスクを **残留リスク** と呼び、経営者がそれを受け入れることを承認します。

#### 取り組み方の選び方

| アプローチ | 中身 | 向いている場面 |
|---|---|---|
| **ベースラインアプローチ** | 規格やガイドラインの標準的な対策を、一律に当てはめる | 手早く一定の水準にしたい |
| **詳細リスク分析** | 資産ごとに脅威と脆弱性を詳しく分析する | 重要な資産 |
| **組合せアプローチ** | 重要な資産は詳細に、それ以外はベースラインで | 実務での標準 |
| **非形式的アプローチ** | 担当者の経験や判断で行う | 小規模・短期間 |

### 4. ISMS と規格

- **ISMS**: リスクアセスメントに基づいて対策を決め、PDCA で継続的に改善する仕組み。要求事項の国際規格は **ISO/IEC 27001**（2022 年版。日本の規格は JIS Q 27001）
- **ISO/IEC 27002**: 管理策（具体的な対策）の手引き。2022 年版で、組織・人・物理・技術の 4 分類に整理された
- **ISMS 認証**: 第三者の審査機関が、組織の ISMS が規格に合っているかを審査して認証する
- **プライバシーマーク**: 個人情報の取扱いが適切な事業者を認定する、日本の制度

### 5. 法律

> [!CAUTION]
> 法律の問題は、<mark>**「何をしたら違反になるか」の範囲を正確に**</mark>。不正アクセス禁止法は、実際に不正ログインしなくても、他人の ID・パスワードを不正に取得・保管すること、フィッシングサイトで入力させようとすることも禁じている。「ログインしなければ罪にならない」は誤り。

| 法律 | 支援士が押さえるべき点 |
|---|---|
| **不正アクセス禁止法** | 他人の ID・パスワードでのログイン、脆弱性を突いた侵入の禁止。ID・パスワードの不正な取得・保管・提供、フィッシングによる入力の要求も処罰の対象。アクセス管理者には、対策を講じる努力義務がある |
| **個人情報保護法** | 漏えいなどで本人の権利を害するおそれが大きい場合（要配慮個人情報、財産的な被害のおそれ、不正の目的によるもの、1,000 人を超えるもの）は、**個人情報保護委員会への報告と本人への通知が義務**。報告は、まず速報（知ってからおおむね 3〜5 日以内）、そのあと確報（30 日以内、不正の目的によるものは 60 日以内） |
| **刑法** | コンピュータウイルスを正当な理由なく作る・提供する・保管すること（不正指令電磁的記録に関する罪）、コンピュータを使った詐欺、データを壊して業務を妨害すること |
| **電気通信事業法** | 通信の秘密を守る義務。通信の中身を調べる対策（メールの検査など）を行うときは、利用者の同意などの整理が必要になる |
| **サイバーセキュリティ基本法** | 国・自治体・重要インフラ事業者などの責務を定める、日本のサイバーセキュリティの基本となる法律 |
| **能動的サイバー防御に関する法律** | 2025 年に成立。重要インフラへの深刻な攻撃に備え、国が通信情報を分析したり、攻撃元のサーバに対処したりする仕組みを、段階的に導入する |

**実例**: Web 編 Ch6 の冒頭で「他人のサービスに試すと法律違反」と書いたのは、不正アクセス禁止法と、刑法の業務妨害の罪のことです。自分の PC の中で、自分が作った脆弱なアプリを攻撃する分には、これらにあたりません。

### 6. 情報処理安全確保支援士の役割

支援士は、組織の中や外部の専門家として、次のような立場で働くことが想定されています。

- 経営者に対して、セキュリティのリスクと対策を **説明し、判断を支援する**
- 情報システムの企画・設計・開発・運用の各段階で、セキュリティの観点から **助言する**
- インシデントが起きたときに、**対応を指揮・支援する**

[SC 編の概要](../README.md) で見た **秘密保持義務** と **信用失墜行為の禁止** は、この立場で他社の弱点や事故の情報に触れるからこそ課されているものです。

## 手を動かすパート

自分の身の回りで、小さなリスクアセスメントをしてみてください。紙か表計算ソフトで十分です。

| 情報資産 | 脅威 | 脆弱性 | 可能性（1〜3） | 影響（1〜3） | 対応 |
|---|---|---|---|---|---|
| スマホの写真 | 紛失・盗難 | 画面ロックが 4 桁の数字 | 2 | 3 | 低減（生体認証、クラウドバックアップ） |
| 大学のレポート | PC の故障 | バックアップなし | 2 | 3 | 低減（クラウドに同期） |
| SNS のアカウント | パスワードリスト攻撃 | パスワードの使い回し | 2 | 2 | 低減（パスワードマネージャー、多要素認証） |

可能性 × 影響の大きいものから手を付ける、というのがリスクの評価です。

## つまずきポイント

> [!CAUTION]
> 管理と法制度の問題は、**言葉の定義の細かい違い** を突いてくる。似た言葉が出たら、誰が・何を・いつまでに、を確かめる。

- <mark>**残留リスクを受け入れる判断は経営者**</mark>: 担当者が決めることではない
- <mark>**NIST CSF 2.0 の「統治」**</mark>: 2.0 で加わった機能
- <mark>**不正アクセス禁止法の範囲**</mark>: ログインしなくても、ID・パスワードの不正取得・保管は違反
- **個人情報の漏えい報告の期限**: 速報はおおむね 3〜5 日、確報は 30 日（不正目的は 60 日）
- **ISO/IEC 27001 と 27002**: 要求事項（認証の基準）と、管理策の手引き

## 重要な単語まとめ

| 用語 | 一言で言うと | 身近な実例 |
|---|---|---|
| **セキュリティガバナンス** | 経営者が方針を示し、監視する仕組み | 取締役会でのセキュリティ報告 |
| **サイバーセキュリティ経営ガイドライン** | 経営者向けの対策の指針 | 委託先を含めた対策 |
| **NIST CSF 2.0** | 統治・識別・防御・検知・対応・復旧の枠組み | 対策の抜けの確認 |
| **リスクアセスメント** | リスクの特定・分析・評価 | 資産ごとのリスク表 |
| **残留リスク** | 対応後に残るリスク | 経営者が受容を承認 |
| **組合せアプローチ** | 重要資産は詳細に、他はベースラインで | 実務の標準 |
| **ISO/IEC 27001 / 27002** | ISMS の要求事項 / 管理策の手引き | ISMS 認証 |
| **不正アクセス禁止法** | 不正ログインと ID の不正取得などの禁止 | フィッシングサイトの開設も対象 |
| **漏えい等の報告義務** | 個人情報保護委員会への報告と本人への通知 | 速報と確報 |
| **不正指令電磁的記録に関する罪** | ウイルスの作成・提供などを罰する | いわゆるウイルス作成罪 |
| **通信の秘密** | 通信の中身を守る義務 | メール検査の同意 |
| **秘密保持義務** | 支援士が仕事で知った秘密を漏らさない義務 | 登録をやめても続く |
