## 本文

### 1. 攻撃の流れ

攻撃者の行動を段階に分けて捉えると、どの段階で食い止めるかを考えやすくなります。代表的なモデルが **サイバーキルチェーン** です。

| 段階 | 攻撃者がすること | 防御側の手 |
|---|---|---|
| 偵察 | 標的の組織の人・システム・公開情報を調べる | 公開情報の見直し |
| 武器化 | マルウェア入りの文書などを用意する | ― |
| 配送 | メール・Web・USB で送り込む | メールフィルタ、利用者の教育 |
| 攻撃 | 脆弱性を突いてマルウェアを実行させる | 修正プログラムの適用、マクロの無効化 |
| インストール | 端末に居座る仕組みを作る | EDR による検知 |
| 遠隔操作 | 外部の指令サーバ（C&C）と通信する | プロキシ・DNS ログの監視 |
| 目的の実行 | 情報の窃取、データの暗号化 | 持ち出しの検知、バックアップ |

<mark>**攻撃者はすべての段階を通らなければ目的を果たせないため、どこか 1 つで止めれば被害を防げる**</mark>。逆に、入口（配送）だけを守っていると、そこを突破されたときに何も気付けない。SC の科目 B では「どの段階で、何によって検知・阻止できたか」がよく問われる。

**MITRE ATT&CK** は、実際の攻撃で観測された手口を、目的（戦術）と方法（技術）の表にまとめた知識ベースです。検知ルールの抜け漏れを確かめたり、インシデント報告で攻撃の手口を共通の言葉で記述したりするのに使われます。

### 2. 侵入後の動き

| 動き | 中身 | 手がかり |
|---|---|---|
| **権限昇格** | 一般利用者の権限から、管理者権限を手に入れる | 管理者グループへの追加、見慣れないサービスの登録 |
| **認証情報の窃取** | メモリやファイルから、パスワードやその代わりになる値（ハッシュ・チケット）を抜き出す | 認証処理を行うプロセスのメモリを読み取る操作 |
| **横展開** | 盗んだ認証情報を使って、ほかの端末やサーバに侵入する | 普段は使わない端末間での管理用通信（リモートデスクトップ・SMB） |
| **持ち出し** | データを圧縮・暗号化して、クラウドストレージなどに送る | 業務時間外の大量の外向き通信 |

**Living off the Land**: OS に最初から入っている正規のツール（PowerShell など）を使って活動し、マルウェアとして検知されにくくする手口です。「正規のツールだから安全」とは言えず、**使われ方** を監視する必要があります。

> [!CAUTION]
> <mark>**管理者のパスワードを全端末で同じにしていると、1 台から盗まれた認証情報で全端末に横展開される**</mark>。端末ごとに異なるローカル管理者のパスワードを自動設定する仕組み（Windows の LAPS など）や、管理者権限の常時付与をやめることが対策として問われる。

### 3. ランサムウェア

- **侵入口**: VPN 機器の脆弱性、リモートデスクトップの公開、フィッシングメール
- **二重脅迫**: データを暗号化するだけでなく、事前に盗み出して「身代金を払わなければ公開する」と脅す手口。バックアップから復旧できても、情報漏えいの被害は残る
- **バックアップの守り方**: 攻撃者はバックアップも狙って消去する。ネットワークから切り離した場所や、書き換えできない形式（イミュータブル）で保管する。**3-2-1 ルール**（3 つのコピーを、2 種類の媒体で、1 つは別の場所に保管する）
- **身代金を払うべきか**: 払ってもデータが戻る保証はなく、攻撃者の資金源になる。国の機関や業界団体は支払わないことを推奨している

### 4. 検知と監視の仕組み

| 仕組み | 役割 |
|---|---|
| **EDR** | 端末上のプロセス・ファイル・通信の動きを記録し、不審な挙動を検知して端末を隔離する |
| **XDR** | 端末だけでなく、メール・ネットワーク・クラウドの情報もまとめて分析する |
| **SIEM** | さまざまな機器のログを 1 か所に集め、組み合わせて（相関分析）異常を見つける |
| **SOAR** | 検知後の定型対応（端末の隔離、アカウントの停止、チケットの起票）を自動化する |
| **ハニーポット** | わざと攻撃を受けさせるおとりのシステム。攻撃の手口を観察する |
| **脅威インテリジェンス** | 攻撃者の手口や指令サーバのアドレスなどの情報。検知ルールに活用する |

#### ログの集め方

- **時刻を同期する**（NTP）: 機器ごとに時刻がずれていると、相関分析ができない
- **ログを改ざんされないように保管する**: 侵入した攻撃者は痕跡を消そうとするため、ログは別のサーバに送って保存する
- **保存期間**: 侵入から発覚まで数か月かかることもあるため、保存期間が短すぎると調査に使えない

### 5. 脆弱性情報の扱い

| 用語 | 中身 |
|---|---|
| **CVE** | 公開された脆弱性に付けられる、世界共通の識別番号（CVE-年-番号） |
| **CVSS** | 脆弱性の深刻度を 0.0〜10.0 で評価する方法。最新は 4.0 版（2023 年）。攻撃の難しさ・必要な権限・影響の大きさなどから算出する |
| **KEV** | 米国 CISA が公開している「実際に悪用が確認された脆弱性」の一覧。深刻度の数値だけでなく、実際に悪用されているかどうかで優先順位を決めるのに使う |
| **JVN** | 日本の脆弱性情報ポータル（JPCERT/CC と IPA が運営） |

<mark>**修正プログラムを適用する優先順位は、CVSS の点数だけでなく、「インターネットから届くか」「実際に悪用されているか」で決めます**</mark>。社内からしかアクセスできない深刻度 9.0 の脆弱性より、外部に公開された VPN 機器で悪用が確認されている脆弱性の方を優先する、といった判断が問われます。

## 手を動かすパート

ログの相関分析がどのようなものか、小さな例で試してみます。次の 2 種類のログから、「VPN にログインした直後に、普段は使わないサーバへリモートデスクトップで接続した利用者」を探します。

```python
vpn = [("09:02", "alice"), ("23:41", "bob"), ("09:15", "carol")]
rdp = [("09:30", "alice", "fileserver"), ("23:44", "bob", "dc01"), ("23:45", "bob", "hr-db")]
usual = {"alice": {"fileserver"}, "bob": {"fileserver"}, "carol": set()}

for t, user in vpn:
    for t2, u2, host in rdp:
        if u2 == user and t2 >= t and host not in usual[user]:
            print(f"要確認: {user} が {t} に VPN 接続、{t2} に {host} へ接続（普段は使わない）")
```

実行すると bob の 2 件が抽出されます。SIEM は、このような照合を大量のログに対して常時行っています。

## つまずきポイント

> [!CAUTION]
> 攻撃と検知の問題では、**「どの段階の、どの痕跡で気付けたか」** を本文のログから読み取る出題が多い。時刻順に並べ直して追跡する。

- <mark>**入口だけを守っても、突破されたら気付けない**</mark>: 検知と対応まで備える
- <mark>**正規ツールの悪用**</mark>: マルウェアとして検知されないため、使われ方を見る
- **バックアップも狙われる**: ネットワークからの切り離しや書き換え不可の設定で保管する
- **CVSS だけで優先順位を決めない**: 外部から到達できるか、実際に悪用されているかを見る
- **ログの時刻同期と保管場所**: 相関分析と改ざん防止の大前提となる

## 重要な単語まとめ

| 用語 | 一言で言うと | 身近な実例 |
|---|---|---|
| **サイバーキルチェーン** | 攻撃を偵察から目的の実行までの段階に分けたモデル | どの段階で止めるかの検討 |
| **MITRE ATT&CK** | 攻撃の戦術と技術をまとめた知識ベース | 検知の抜け漏れの確認 |
| **権限昇格 / 横展開** | 管理者権限を得る / ほかの端末へ広がる | 社内全体への感染拡大 |
| **Living off the Land** | 正規のツールを悪用して活動する手口 | PowerShell の悪用 |
| **LAPS** | 端末ごとに異なる管理者パスワードを自動設定する仕組み | 横展開の防止 |
| **二重脅迫** | 暗号化 ＋ 窃取したデータの公開による脅迫 | ランサムウェア |
| **3-2-1 ルール / イミュータブル** | バックアップの保有ルール / 書き換え不可の保管 | 攻撃者に消されないバックアップ |
| **EDR / XDR** | 端末の挙動の監視 / 複数領域をまとめて分析 | 社内 PC の監視ソフト |
| **SIEM / SOAR** | ログの集約と相関分析 / 対応の自動化 | SOC の基盤 |
| **CVE / CVSS / KEV** | 脆弱性の番号 / 深刻度 / 悪用が確認された一覧 | 修正の優先順位付け |
| **JVN** | 日本の脆弱性情報ポータル | 国内製品の脆弱性情報 |
