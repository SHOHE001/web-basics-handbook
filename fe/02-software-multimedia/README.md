## 本文

### 1. ソフトウェアの分類

| 分類 | 役割 | 例 |
|---|---|---|
| **基本ソフトウェア（OS）** | ハードウェアを管理し、アプリが使える土台を用意する | Windows、macOS、Linux、Android、iOS |
| **ミドルウェア** | OS とアプリの間で、多くのアプリが共通して使う機能を提供する | DBMS（PostgreSQL など）、Web サーバー（Nginx） |
| **応用ソフトウェア（アプリ）** | 利用者の目的そのものの処理を行う | ブラウザ、LINE、表計算ソフト |

Web 編 Ch7 で登場した Nginx や PostgreSQL は、この分類では **ミドルウェア** にあたります。

### 2. OS の仕事

OS の中心部分を **カーネル** と呼びます。カーネルが担う主な仕事は次のとおりです。

- **タスク管理（プロセス管理）**: 実行中のプログラムに CPU を順番に割り当てる
- **記憶管理**: メモリをプログラムに割り当て、足りない分を補助記憶で補う
- **入出力管理**: デバイスドライバを通じて周辺機器を動かす
- **ファイル管理**: ファイルとディレクトリを管理する
- **ユーザー管理**: ログインや権限を管理する

#### タスクの状態遷移

OS は、実行中のプログラム（タスク）を 3 つの状態で管理します。

```
            CPU が割り当てられる（ディスパッチ）
  [実行可能] ─────────────────────→ [実行]
      ↑   ←───────────────────────   │
      │    持ち時間切れ・より優先の     │ 入出力の完了待ちなど
      │    タスクが来た                │
      │                               ↓
      └──────── 待ちが解けた ──────── [待ち]
```

ポイントは、<mark>**待ち状態から直接「実行」には戻らず、いったん「実行可能」の列に並び直す**</mark> ことです。

**実例**: スマホで動画アプリを開いたままメッセージアプリに切り替えると、動画アプリは裏に回って CPU をほとんど使わなくなります。これは、OS が「今は実行しなくてよい」と判断し、表のアプリに CPU を割り当てているためです。

#### スケジューリング方式

| 方式 | 中身 |
|---|---|
| **到着順（FCFS）** | 到着した順に最後まで実行する |
| **ラウンドロビン** | 一定時間（タイムクウォンタム）ずつ順番に実行し、時間が来たら列の最後に回す |
| **優先度順** | 優先度の高いタスクから実行する |
| **処理時間順** | 処理時間の短いタスクから実行する |

#### 割込み

実行中の処理を中断して、急ぎの処理を優先させる仕組みが **割込み** です。

- **内部割込み**: 実行中のプログラム自身が原因で起こるもの（0 で割った、存在しないメモリを読もうとした、など）
- **外部割込み**: プログラムの外部が原因で起こるもの（入出力の完了、タイマー、電源の異常など）

### 3. 仮想記憶

> [!CAUTION]
> 仮想記憶は「メモリを増やす魔法」ではなく、<mark>**主記憶に入りきらない部分を補助記憶に退避させ、主記憶より大きなメモリがあるように見せる仕組み**</mark>です。補助記憶とのやり取りが増えると処理が遅くなる、という代償とセットで出題されます。

プログラムは、一定の大きさに区切った **ページ** 単位で主記憶と補助記憶を行き来します（**ページング方式**）。

- 必要なページが主記憶にないことを **ページフォールト** と呼ぶ
- 主記憶が満杯なら、どれか 1 ページを補助記憶に追い出して（**ページアウト**）、必要なページを読み込む（**ページイン**）
- ページの出し入れが多すぎて処理がほとんど進まない状態を **スラッシング** と呼ぶ

**実例**: パソコンでブラウザのタブを何十個も開くと、急に全体が重くなることがあります。これはメモリが足りなくなり、OS が補助記憶との出し入れを頻繁に始めたサインです。

#### ページ置換えアルゴリズム

どのページを追い出すかを決めるルールです。

| 方式 | 追い出すページ |
|---|---|
| **FIFO** | いちばん先に主記憶に入ったページ |
| **LRU** | いちばん長い間 **使われていない** ページ |
| **LFU** | 使われた **回数** がいちばん少ないページ |

FIFO と LRU は名前が似ていないにもかかわらず混同しやすいため、「入った順か、使った順か」で区別します。

### 4. ファイルとディレクトリ

ファイルはディレクトリ（フォルダ）の木構造で管理されます。いちばん上の階層を **ルートディレクトリ**、現在作業している場所を **カレントディレクトリ** と呼びます。

| 書き方 | 意味 |
|---|---|
| **絶対パス** | ルートから順にたどる書き方（例: `/home/user/notes/a.txt`） |
| **相対パス** | カレントディレクトリを基準にした書き方（例: `notes/a.txt`） |
| `.` | カレントディレクトリ自身 |
| `..` | 1 つ上（親）のディレクトリ |

**実例**: このハンドブックの各章の最後にある `[次の章へ](../02-network/README.md)` のリンクは相対パスです。`..` で 1 つ上の `chapters/` に戻り、そこから隣の章のディレクトリに入っています。

#### バックアップ

| 方式 | 取るもの | 復元に必要なもの |
|---|---|---|
| **フルバックアップ** | すべてのデータ | フル 1 つ |
| **差分バックアップ** | 前回の **フル** 以降に変更された分 | フル ＋ 最新の差分 |
| **増分バックアップ** | 前回の **バックアップ（種類を問わない）** 以降に変更された分 | フル ＋ それ以降の増分すべて |

### 5. 開発ツールと OSS

#### コンパイラとインタプリタ

| | コンパイラ | インタプリタ |
|---|---|---|
| 動き | ソースコード全体を先に機械語へ翻訳してから実行する | 1 行（1 命令）ずつ翻訳しながら実行する |
| 特徴 | 実行が速い | 書いてすぐに試せる |
| 代表 | C、Go | Python、JavaScript（※実際の処理系は両方の工夫を組み合わせている） |

翻訳されたプログラムどうしやライブラリを結合して 1 つの実行可能なファイルにまとめるのが **リンカ**、実行時にメモリへ読み込むのが **ローダ** です。

#### OSS（オープンソースソフトウェア）

ソースコードが公開されており、決められた条件のもとで誰でも利用・改変・再配布できるソフトウェアです。Linux、Python、Firefox などが代表例です。利用条件は **ライセンス** で定められています。

- **GPL**: 改変したものを配布するときは、その改変版も同じ GPL でソースコードを公開しなければならない（**コピーレフト**）
- **MIT ライセンス、BSD ライセンス**: 著作権表示などを残せば、改変版を非公開にしてもよい

OSS は「無料で何をしてもよい」わけではありません。ライセンス条件を守る必要があります。

### 6. マルチメディア

#### 画像のデータ量

画像は、細かい点（**画素、ピクセル**）の集まりです。1 画素の色を何ビットで表すかを **色深度** と呼びます。

- 光の三原色（R・G・B）を各 8 ビットで表すと 1 画素あたり 24 ビットになり、約 1,677 万色（2²⁴ 色）を表現できる（**フルカラー**）
- データ量 ＝ 横の画素数 × 縦の画素数 × 1 画素のビット数

**例題**: 1,920 × 1,080 画素、24 ビットフルカラーの画像（無圧縮）は何バイトでしょうか。

1,920 × 1,080 × 24 ÷ 8 ＝ 6,220,800 バイト ≒ **約 6.2 MB**

**実例**: テレビやモニターの「フル HD」がこの 1,920 × 1,080 です。4K は縦横がそれぞれおよそ 2 倍になるため、データ量は約 4 倍になります。

#### 音声のデータ量

アナログの音（連続した波）をデジタルデータにするには、一定の間隔で波の高さを測り（**標本化、サンプリング**）、その高さを段階的な数値に置き換えます（**量子化**）。この方式を **PCM** と呼びます。

- **サンプリング周波数**: 1 秒間に何回測るか（Hz）
- **量子化ビット数**: 高さを何ビットで表すか

```
1 秒あたりのデータ量（ビット）＝ サンプリング周波数 × 量子化ビット数 × チャンネル数
```

**例題**: 音楽 CD（44.1 kHz、16 ビット、ステレオ 2 チャンネル）の 1 秒分のデータ量はいくらでしょうか。

44,100 × 16 × 2 ＝ 1,411,200 ビット ＝ 176,400 バイト ≒ **約 176 KB/秒**

#### 圧縮

| 種類 | 意味 | 例 |
|---|---|---|
| **可逆圧縮** | 元のデータに完全に戻せる | ZIP、PNG、GIF、FLAC |
| **非可逆圧縮** | 人が気付きにくい情報を削って小さくするため、完全には元に戻らない | JPEG（写真）、MP3・AAC（音声）、MPEG・H.264（動画） |

> [!CAUTION]
> <mark>**JPEG は非可逆、PNG は可逆**</mark>です。スクリーンショットや文字の入った図は PNG、写真は JPEG と使い分けるのが基本です。この区別はほぼ毎回のように選択肢に登場します。

**実例**: LINE で写真を送ると画質が少し落ちるのは、送信時に非可逆圧縮を行ってデータ量を減らしているためです。

#### そのほかの用語

- **VR（仮想現実）**: ゴーグルなどを使い、作られた空間に入り込む体験
- **AR（拡張現実）**: 現実の映像にデジタル情報を重ね合わせる技術（スマホのカメラ越しにキャラクターが見えるゲームなど）
- **CG**: コンピュータで作る画像。立体を描く 3DCG では、光の反射をシミュレーションする **レイトレーシング** などの技法がある

## 手を動かすパート

この章で扱う計算は 2 つ（画像・音声のデータ量）だけなので、FE Chapter 1 の `cpu_calc.py` と同じ要領で Python の対話モードを使って確かめられます。

```python
>>> 1920 * 1080 * 24 / 8          # 画像（バイト）
6220800.0
>>> 44100 * 16 * 2 / 8            # 音声 1 秒（バイト）
176400.0
```

## つまずきポイント

> [!CAUTION]
> 名前が似ていて **取り違えやすい** ペアのリストです。試験の選択肢は、この取り違えを狙って作られています。

- <mark>**FIFO と LRU**</mark>: 「最初に入ったもの」と「最も長く使われていないもの」は別物
- <mark>**差分と増分**</mark>: 差分は「前回のフル」から、増分は「前回のバックアップ」からの変更分。復元時に必要なデータの数が変わる
- **待ち → 実行 には直接進まない**: 必ず「実行可能」を経由する
- **ビットとバイト**: データ量の計算では、最後に 8 で割ってバイトに換算するのを忘れない
- **OSS ＝ 無条件で自由、ではない**: GPL のコピーレフトでは「改変版も公開すること」が条件になる

## 重要な単語まとめ

| 用語 | 一言で言うと | 身近な実例 |
|---|---|---|
| **OS / カーネル** | ハードウェアを管理する基本ソフト / その中心部 | Windows、Android |
| **ミドルウェア** | OS とアプリの間で動く共通機能 | PostgreSQL、Nginx |
| **タスクの 3 状態** | 実行・実行可能・待ち | 裏に回ったアプリは CPU を使わない |
| **ラウンドロビン** | 一定時間ずつ順番に CPU を割り当てる方式 | 何人かでゲーム機を交代で使う |
| **割込み** | 実行中の処理を中断して急ぎの処理を行わせる仕組み | 入出力の完了通知 |
| **仮想記憶 / ページフォールト** | 主記憶より大きなメモリに見せる仕組み / 必要なページが主記憶にない状態 | タブを開きすぎると重くなる |
| **スラッシング** | ページの出し入ればかりで処理が進まない状態 | メモリ不足で PC が固まる |
| **LRU / FIFO** | 最も長く使っていないものを追い出す / 最初に入ったものを追い出す | ページ置換えの方式 |
| **絶対パス / 相対パス** | ルートからの書き方 / 今いる場所からの書き方 | `../02-network/README.md` |
| **コンパイラ / インタプリタ** | まとめて翻訳する / 1 行ずつ翻訳しながら実行する | C / Python |
| **OSS / GPL** | ソースコード公開のソフト / 改変版にも公開を求めるライセンス | Linux |
| **画素 / 色深度** | 画像を構成する点 / 1 点の色を表すビット数 | フル HD、24 ビットフルカラー |
| **サンプリング周波数 / 量子化ビット数** | 1 秒間に測る回数 / 波の高さを表すビット数 | 音楽 CD は 44.1 kHz・16 ビット |
| **可逆圧縮 / 非可逆圧縮** | 元に戻せる圧縮 / 完全には戻せない圧縮 | PNG / JPEG |
