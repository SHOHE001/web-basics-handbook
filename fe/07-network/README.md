## 本文

### 1. LAN と WAN

- **LAN**: 家・学校・会社の建物の中など、限られた範囲のネットワーク
- **WAN**: 離れた拠点どうしを、通信事業者の回線でつないだ広い範囲のネットワーク
- **インターネット**: 世界中のネットワークを相互につないだもの（Web 編 Ch1）

LAN の配線のしかた（トポロジ）には、中央の機器から放射状につなぐ **スター型**、1 本のケーブルに並べてつなぐ **バス型**、輪のようにつなぐ **リング型** があります。現在の有線 LAN（イーサネット）はほぼスター型です。

#### 通信方式

- **回線交換**: 通信している間、回線を専有する方式（昔の固定電話）
- **パケット交換**: データを小さな **パケット** に分割して送り、回線を多くの人で共有する方式（インターネット）

### 2. OSI 基本参照モデルと機器

Web 編 Ch2 では TCP/IP の 4 層で考えましたが、試験では **OSI の 7 層** と、各層で中継する機器の組合せがよく出題されます。

| 層 | 名前 | 役割 | 中継する機器 |
|---|---|---|---|
| 7 | アプリケーション層 | アプリどうしのやり取りの決まり | ゲートウェイ |
| 6 | プレゼンテーション層 | データの表現形式（文字コード・暗号化など） | ゲートウェイ |
| 5 | セッション層 | 通信の開始から終了までの管理 | ゲートウェイ |
| 4 | トランスポート層 | 確実に届ける（TCP）／速く届ける（UDP） | ゲートウェイ |
| 3 | ネットワーク層 | どこからどこへ届けるか（IP アドレスで経路を決める） | **ルータ**、L3 スイッチ |
| 2 | データリンク層 | 隣の機器まで届ける（MAC アドレス） | **ブリッジ**、**L2 スイッチ（スイッチングハブ）** |
| 1 | 物理層 | 電気・光・電波の信号への変換 | **リピータ**、**リピータハブ** |

> [!CAUTION]
> <mark>**ルータは第 3 層（IP アドレスで中継）、スイッチングハブは第 2 層（MAC アドレスで中継）、リピータは第 1 層（信号を増幅するだけ）**</mark>。「どの層の機器が、何の情報を見て中継するか」という組合せは毎回のように出題される。機器の名前と参照する情報（IP か MAC か）をセットで覚えること。

**実例**: 家庭用の Wi-Fi ルーターは、実は何役も兼ねた機器です。家の中の LAN と外のインターネットをつなぐ **ルータ**（第 3 層）、背面の LAN ポートで有線機器をつなぐ **スイッチングハブ**（第 2 層）、無線で端末をつなぐ **アクセスポイント**、さらに NAT や DHCP の機能まで備えています。

### 3. TCP/IP のプロトコルとポート番号

| プロトコル | 役割 | ポート |
|---|---|---|
| **HTTP / HTTPS** | Web の通信（Web 編 Ch3） | 80 / 443 |
| **SMTP** | メールの **送信**（およびサーバ間の転送） | 25（利用者からの送信には 587 が使われることが多い） |
| **POP3** | メールの受信。サーバから端末に **ダウンロード** する | 110 |
| **IMAP** | メールの受信。メールを **サーバ上に置いたまま** 閲覧する | 143 |
| **FTP** | ファイル転送 | 20 / 21 |
| **SSH** | 暗号化された遠隔ログイン | 22 |
| **DNS** | ドメイン名と IP アドレスの対応付け（Web 編 Ch2） | 53 |
| **DHCP** | 端末に IP アドレスなどを自動で割り当てる | 67 / 68 |
| **NTP** | 時刻を合わせる | 123 |

**実例**: Gmail をスマホとパソコンの両方で開いたとき、どちらでも既読状態が同期されるのは、メールをサーバ上に置いたままにする IMAP のような仕組みで動いているからです。POP3 で受信するとメールが端末にダウンロードされるため、別の端末からは見られなくなることがあります（設定によってサーバに残すことも可能です）。

#### 電子メールの仕組みと拡張

- **MIME**: 本来は英数字しか送れないメールで、日本語や添付ファイルを扱えるようにする拡張規格。Web 編 Ch4 に登場した MIME タイプの由来でもある
- **S/MIME**: メールを暗号化し、電子署名を付ける仕組み

### 4. IP アドレスとサブネット

#### IP アドレスの構造

IPv4 アドレスは 32 ビットで構成され、**ネットワーク部**（どの LAN か）と **ホスト部**（その LAN 内のどの端末か）に分かれます。その境目を示すのが **サブネットマスク** です（Web 編 Ch2）。

#### ホスト数の計算

> [!CAUTION]
> <mark>**割り当てられるホスト数 ＝ 2^(ホスト部のビット数) − 2**</mark>。2 を引くのは、ホスト部が **全部 0**（ネットワークそのものを表すアドレス）と **全部 1**（全員宛ての **ブロードキャストアドレス**）のものは端末に割り当てられないためである。この「− 2」を忘れた数値が必ず選択肢に含まれている。

**例題**: `192.168.10.0/26` のネットワークにおいて、端末に割り当てられるアドレスはいくつあるか。

- `/26` はネットワーク部が 26 ビット → ホスト部は 32 − 26 ＝ 6 ビット
- 2⁶ − 2 ＝ 64 − 2 ＝ **62 個**

サブネットマスクを 10 進数で表すと、上位 26 ビットが 1 なので `255.255.255.192` となります（最後の 8 ビットが `11000000` ＝ 192）。

#### ネットワークアドレスの求め方

IP アドレスとサブネットマスクを **AND 演算** します（FE Chapter 3）。

```
IP アドレス   192.168.10.77   → 最後の 8 ビット 01001101
マスク        255.255.255.192 → 最後の 8 ビット 11000000
AND                           →                01000000 ＝ 64
ネットワークアドレス: 192.168.10.64
```

この端末は `192.168.10.64`〜`192.168.10.127` のネットワークに属しており、`192.168.10.127` がブロードキャストアドレスとなります。

#### CIDR

`/26` のように、ネットワーク部の長さをビット単位で自由に決める方式を **CIDR** と呼びます。

#### IPv6

アドレスの長さを 128 ビットに拡張した新しい規格です（Web 編 Ch2）。事実上使い切れないほどのアドレス数があるため、NAT を使わずに端末ごと固有のグローバルなアドレスを持てます。

### 5. アドレスを扱う仕組み

| 仕組み | 役割 | 身近な例 |
|---|---|---|
| **DHCP** | 端末がネットワークにつながった際、IP アドレス・サブネットマスク・デフォルトゲートウェイ・DNS サーバを自動で設定する | 大学の Wi-Fi に接続すると自動でアドレスが割り当てられる |
| **ARP** | IP アドレスから、同じ LAN 内の通信相手の MAC アドレスを調べる | LAN 内での通信の前準備 |
| **NAT** | プライベート IP アドレスとグローバル IP アドレスを 1 対 1 で変換する | ― |
| **NAPT（IP マスカレード）** | ポート番号も併用して、1 つのグローバル IP を **複数の端末で共有** する | 家のルーター（Web 編 Ch2 の「NAT」は、正確にはこちらを指す） |
| **デフォルトゲートウェイ** | 自分の LAN 以外に向けた通信を最初に渡す、出口となるルータ | 家の Wi-Fi ルーター |

### 6. 伝送時間の計算

```
伝送時間 ＝ データ量 ÷ (回線速度 × 伝送効率)
```

- **回線速度** の単位は bps（ビット毎秒）。1 秒間に何ビット送れるかを表す
- **伝送効率** は、制御用のデータなどを除き、実際のデータ送信に使える割合を表す

**例題**: 100 M バイトのファイルを、回線速度 100 Mbps・伝送効率 80% の回線で送ると何秒かかるか。

1. データ量をビットに換算する: 100 × 10⁶ バイト × 8 ＝ 8 × 10⁸ ビット
2. 実効速度を求める: 100 × 10⁶ × 0.8 ＝ 8 × 10⁷ ビット/秒
3. 伝送時間を求める: 8 × 10⁸ ÷ (8 × 10⁷) ＝ **10 秒**

<mark>**回線速度はビット、ファイルサイズはバイト**</mark> で表記されることがほとんどなので、8 倍して単位をそろえるのを忘れないことが最大のポイントです。

**実例**: 「光回線 1Gbps」を契約していても、1 GB のゲームのダウンロードが 1 秒で終わらないのは、1 GB ＝ 8 Gb であることや、伝送効率の低下・回線の混雑があるためです。

### 7. 無線 LAN とモバイル通信

#### 無線 LAN

- 規格は **IEEE 802.11** シリーズ。Wi-Fi 6（802.11ax）、Wi-Fi 7（802.11be）などがある
- **SSID**: 無線 LAN のネットワークを識別する名前（スマホの Wi-Fi 一覧に表示される名前）
- **アクセスポイント**: 無線端末をネットワークにつなぐ機器
- 暗号化方式は **WPA3** が最新。古い WEP は簡単に解読されるため使わない
- 2.4 GHz 帯は遠くまで届くが電子レンジなどの電波と干渉しやすく、5 GHz 帯は高速だが壁などの障害物に弱い

#### モバイル通信と IoT

- **5G**: 高速・大容量、低遅延、多数同時接続を特徴とする移動通信システム
- **LPWA**: 少ない電力で遠くまで通信できる、IoT 向けの通信方式（通信速度は遅い）
- **IoT**: さまざまな「モノ」がネットワークにつながること（スマート家電、センサーなど）
- **テザリング**: スマホを親機として使い、パソコンなどをインターネットにつなぐ機能
- **ローミング**: 契約している通信事業者のエリア外で、提携する別事業者の設備を借りて通信する仕組み（海外旅行時など）

### 8. ネットワークの管理

- **ping**: 通信相手に到達できるかを確認するコマンド（ICMP というプロトコルを使う）
- **SNMP**: ネットワーク機器の状態を収集して監視するプロトコル
- **VLAN**: 物理的な配線とは無関係に、スイッチの設定によって LAN を論理的に分割する技術
- **SDN**: ネットワーク機器の設定や制御を、ソフトウェアで一元管理する考え方

## 手を動かすパート

Python 標準の `ipaddress` モジュールを使うと、サブネットの計算をそのままコードで確認できます。

```python
>>> import ipaddress
>>> net = ipaddress.ip_network("192.168.10.64/26")
>>> net.netmask
IPv4Address('255.255.255.192')
>>> net.num_addresses - 2          # 割り当てられるホスト数
62
>>> net.broadcast_address
IPv4Address('192.168.10.127')
>>> ipaddress.ip_interface("192.168.10.77/26").network
IPv4Network('192.168.10.64/26')
```

Web 編 Ch2 の `code/01_dns_lookup.py`（名前解決）と `03_tcp_connect.py`（TCP 接続）も、この章で扱ったアプリケーション層・トランスポート層の復習になります。

## つまずきポイント

> [!CAUTION]
> ネットワークの計算問題は、**単位の換算と例外の「− 2」** の見落としで失点することが多い。計算を始める前に、単位と条件を書き出すこと。

- <mark>**ホスト数の「− 2」**</mark>: ホスト部が全部 0 と全部 1 のアドレスは端末に割り当てられない
- **ビットとバイトの換算**: 伝送時間の計算では 8 倍の換算を忘れない
- <mark>**POP3 と IMAP**</mark>: メールを端末にダウンロードするか、サーバに置いたまま閲覧するか
- **NAT と NAPT**: 1 つのグローバル IP を複数台で共有できるのは、ポート番号も変換する NAPT
- **ルータとスイッチの層**: ルータ ＝ 第 3 層・IP、スイッチングハブ ＝ 第 2 層・MAC
