## 本文

### 1. 情報セキュリティの 3 要素

| 要素 | 意味 | 損なわれる例 |
|---|---|---|
| **機密性**（Confidentiality） | 許可された人だけが見られる | 個人情報の漏えい |
| **完全性**（Integrity） | 内容が正しく、改ざんされていない | Web ページの改ざん |
| **可用性**（Availability） | 使いたいときに使える | DoS 攻撃でサービス停止 |

頭文字をとって **CIA** と呼ばれます。これに **真正性**（本物であること）、**責任追跡性**（誰の操作か後から追跡できること）、**否認防止**（操作したことを後から否定させないこと）、**信頼性**（意図どおりに動作すること）を加えることもあります。

### 2. リスクの考え方

- **脅威**: 被害を引き起こす原因（攻撃者、ウイルス、地震、操作ミス）
- **脆弱性**: 脅威につけ込まれる弱点（パッチが適用されていないソフト、弱いパスワード）
- **リスク**: 脅威が脆弱性につけ込み、損害が生じる可能性

リスクは「どのくらい起きやすいか × 起きたらどのくらい被害が大きいか」で評価し、対応を決めます。

| リスク対応 | 中身 | 例 |
|---|---|---|
| **回避** | リスクの原因そのものをやめる | 危険なサービスの提供をやめる |
| **低減** | 起きにくくし、被害を小さくする | ウイルス対策ソフト、バックアップ |
| **移転（共有）** | 他者に負担してもらう | サイバー保険、運用の外部委託 |
| **受容（保有）** | 影響が小さいため受け入れる | 対策費の方が高くつく場合 |

### 3. マルウェア

悪意のあるソフトウェアの総称です。

| 種類 | 特徴 |
|---|---|
| **ウイルス** | 他のプログラムに寄生して増殖する |
| **ワーム** | 単独で存在し、ネットワークを通じて自身を複製して広がる |
| **トロイの木馬** | 便利なソフトを装って入り込み、裏で不正な動作をする |
| **ランサムウェア** | ファイルを暗号化して使えなくし、復元と引き換えに身代金を要求する。最近は「データを公開する」と二重に脅迫する手口も多い |
| **スパイウェア / キーロガー** | 利用者の情報やキーボードの入力内容を盗み取る |
| **ボット** | 感染した端末を外部から遠隔操作できるようにする。大量のボットの集団（ボットネット）は DDoS 攻撃に悪用される |
| **ルートキット** | 侵入の痕跡を隠蔽するためのツール一式 |

### 4. 代表的な攻撃手法

#### 人をだます攻撃

- **ソーシャルエンジニアリング**: 技術的手法ではなく、人の心理的な隙を突く手法。電話で上司や担当者になりすましてパスワードを聞き出す、肩越しに画面をのぞき見る（ショルダーハッキング）、ゴミ箱から書類を探り出す（トラッシング）など
- **フィッシング**: 本物そっくりの偽サイトやメールに誘導し、ID やパスワード、カード番号を入力させる。SMS を悪用するものはスミッシングと呼ばれる
- **標的型攻撃**: 特定の組織を狙い、取引先などを装ったメールでマルウェアを実行させる
- **ビジネスメール詐欺（BEC）**: 取引先や経営者になりすまし、偽の口座へ送金させる

**実例**: 「荷物をお届けしましたが不在でした」「アカウントが停止されます」といった SMS 内のリンクは、ほぼフィッシングです。正規のアプリやブックマークから公式サイトを開いて確認するのが基本的な対処法です。

#### パスワードを狙う攻撃

| 攻撃 | 中身 | 効く対策 |
|---|---|---|
| **総当たり（ブルートフォース）** | 1 つのアカウントに対し、全パターンを順番に試す | 一定回数の失敗によるロック |
| **辞書攻撃** | よく使われる単語や文字列を順番に試す | 推測されにくいパスワードの設定 |
| **リバースブルートフォース** | よくあるパスワード 1 つを固定し、ID を次々に変えて試す | ロックが効きにくいため、多要素認証が有効 |
| **パスワードリスト攻撃** | 他のサービスから流出した ID とパスワードの組み合わせをそのまま試す | <mark>**パスワードを使い回さない**</mark>、多要素認証 |

#### サービスや通信を狙う攻撃

- **DoS / DDoS 攻撃**: 大量の通信を送りつけてサービスを停止させる（可用性を損なう）。多数の端末から一斉に行うものが DDoS
- **中間者攻撃**: 通信の途中に割り込み、内容を盗み見たり書き換えたりする。TLS で防げる（Web 編 Ch3）
- **DNS キャッシュポイズニング**: DNS サーバのキャッシュに偽の情報を記憶させ、偽サイトへ誘導する
- **ゼロデイ攻撃**: 脆弱性が発見されてから、修正プログラム（パッチ）が提供される前にその弱点を突く攻撃
- **SQL インジェクション・XSS・CSRF**: Web アプリに対する攻撃（Web 編 Ch6 で再現済み）
- **ディレクトリトラバーサル**: `../` を使ってファイルパスをさかのぼり、非公開のファイルを読み取る
- **サプライチェーン攻撃**: 防御の固い標的へ直接向かわず、取引先や使用しているソフトウェア部品を経由して侵入する

### 5. 暗号

暗号化する前の文を **平文**、暗号化した後の文を **暗号文**、暗号化と復号に用いる値を **鍵** と呼びます。

#### 共通鍵暗号と公開鍵暗号

| | 共通鍵暗号 | 公開鍵暗号 |
|---|---|---|
| 鍵 | 暗号化と復号に **同じ鍵** を使う | **公開鍵** と **秘密鍵** のペアを使う |
| 速さ | 速い | 遅い |
| 困りごと | 鍵を相手に安全に渡す手段が必要 | 処理が重い |
| 代表 | AES | RSA、楕円曲線暗号 |
| n 人が互いに通信するのに必要な鍵の数 | n(n − 1) ÷ 2 個 | 2n 個（1 人 1 ペア） |

> [!CAUTION]
> 公開鍵暗号で秘密の文書を送るときは、<mark>**受信者の公開鍵で暗号化し、受信者が自身の秘密鍵で復号する**</mark>。一方、次に出てくるデジタル署名では **送信者の秘密鍵で署名し、受信者が送信者の公開鍵で検証する**。「誰の」「どちらの」鍵を使うかの組み合わせは頻出である。

**例題**: 10 人が互いに秘密の通信を行う場合、共通鍵暗号なら 10 × 9 ÷ 2 ＝ **45 個**、公開鍵暗号なら 10 × 2 ＝ **20 個** の鍵が必要です。人数が増えるほど、必要な鍵の数の差は広がります。

#### ハイブリッド暗号

実際の通信では、双方の長所を組み合わせます。**公開鍵暗号で共通鍵を安全に受け渡し、本体のデータは処理が速い共通鍵暗号で暗号化します**。Web 編 Ch3 の TLS ハンドシェイクで「共通鍵を作る」と説明したのは、この仕組みのことです。

#### ハッシュ関数

任意の長さのデータから、固定長の値（**ハッシュ値**）を算出する関数です。SHA-256 などが代表的です。

- 同じデータからは必ず同じハッシュ値が得られる
- 1 文字でも変わると、ハッシュ値はまったく異なるものになる
- ハッシュ値から元のデータを復元することはできない（一方向性）

ダウンロードしたファイルが破損したり改ざんされたりしていないかを確かめる（完全性の確認）ために使われます。パスワードを保存する際は、専用のハッシュ関数（bcrypt、Argon2 など）を用います（Web 編 Ch6）。

### 6. デジタル署名と PKI

#### デジタル署名

「この文書は確かに本人が作成し、途中で改ざんされていない」ことを証明する仕組みです。

1. 送信者は文書のハッシュ値を求め、それを **送信者の秘密鍵** で暗号化する（これが署名になる）
2. 文書と署名を送信する
3. 受信者は署名を **送信者の公開鍵** で復号し、自身で計算した文書のハッシュ値と照合する
4. 一致すれば「本人が作成した（秘密鍵を持つのは本人のみ）」「改ざんされていない」と確認できる

<mark>**デジタル署名で確認できるのは「本人であること」と「改ざんされていないこと」**</mark>です。文書の内容を秘匿する（機密性を保つ）機能はありません。

#### PKI と認証局

「その公開鍵が本当に本人（またはそのサイト）のものか」を保証する機関が **認証局（CA）** であり、公開鍵に認証局が署名したものが **デジタル証明書** です。この仕組み全体を **PKI（公開鍵基盤）** と呼びます。

**実例**: ブラウザの鍵マークをクリックすると表示される証明書がこれにあたります（Web 編 Ch3）。Let's Encrypt などの認証局が「この公開鍵は確かに example.com のものである」と署名しています。有効期限内に失効した証明書の一覧は **CRL**（証明書失効リスト）で確認します。

### 7. 利用者認証

本人確認の方法は、大きく 3 種類（**認証の 3 要素**）に分類されます。

| 要素 | 例 |
|---|---|
| **知識**（知っているもの） | パスワード、暗証番号、秘密の質問 |
| **所有**（持っているもの） | スマホ、IC カード、ハードウェアキー |
| **生体**（本人の身体の特徴） | 指紋、顔、静脈、虹彩 |

- **多要素認証**: 異なる要素を 2 つ以上組み合わせる方式。「パスワード ＋ スマホに届くコード」などが該当する。パスワードを 2 回求めるのは同じ要素の組み合わせなので多要素認証にはならない
- **ワンタイムパスワード**: 1 回限り有効なパスワード。認証アプリに 30 秒ごとに表示される数字など
- **シングルサインオン（SSO）**: 1 回の認証で複数のサービスを利用できるようにする仕組み。「Google でログイン」など
- **CAPTCHA**: ゆがんだ文字の入力や画像の選択によって、操作しているのが人間かプログラムかを判別する
- **パスキー**: パスワードの代わりに、端末に保存された秘密鍵と生体認証などを組み合わせてログインする方式。偽サイトでは作動しないためフィッシングに強い

生体認証では、本人を誤って拒否してしまう確率（**本人拒否率**）と、他人を誤って受け入れてしまう確率（**他人受入率**）がトレードオフの関係にあります。

### 8. 技術的な対策

| 対策 | 役割 |
|---|---|
| **ファイアウォール** | IP アドレスやポート番号を確認し、許可された通信だけを通す（パケットフィルタリング） |
| **WAF** | Web アプリへの通信の **中身** を検査し、SQL インジェクションや XSS といった攻撃パターンを遮断する |
| **IDS / IPS** | 不正な通信を検知する（IDS）／検知して遮断まで行う（IPS） |
| **DMZ** | 社内ネットワークとインターネットの間に設ける緩衝地帯。外部に公開する Web サーバなどを配置し、万一侵入されても社内ネットワークへ被害が及びにくくする |
| **VPN** | インターネット上に暗号化された仮想的な専用線を構築する。自宅から社内ネットワークへ接続する際などに使われる |
| **プロキシサーバ** | 社内端末の代わりに外部と通信する中継サーバ。閲覧制限やログの記録に用いられる |
| **検疫ネットワーク** | 社外から持ち込まれた PC を、安全性が確認されるまで隔離されたネットワークに接続させる仕組み |
| **ペネトレーションテスト** | 実際に疑似的な攻撃を行い、システムの弱点を洗い出す検査 |
| **デジタルフォレンジックス** | インシデント発生後に、証拠となるデータを保全・分析する調査手法 |

近年は「社内ネットワークなら安全」という前提を捨て、すべてのアクセスを毎回検証する **ゼロトラスト** という考え方も普及しています。

### 9. 組織としての対策

- **情報セキュリティポリシー**: 組織としてのセキュリティ方針（基本方針・対策基準・実施手順）
- **ISMS**: 情報セキュリティを継続的に管理・運用する仕組み。**PDCA サイクル**（計画・実行・点検・改善）を回して維持する。国際規格は ISO/IEC 27001、国内規格は JIS Q 27001
- **CSIRT**: セキュリティ事故（インシデント）が発生した際に対応する組織内の専門チーム
- **SOC**: ネットワークや機器を 24 時間体制で監視し、攻撃の検知や分析を行う組織
- **IPA の「情報セキュリティ 10 大脅威」**: その年に社会的影響が大きかった脅威を IPA が毎年まとめているもの。ランサムウェアや標的型攻撃が毎年上位に挙げられている

関連法規（不正アクセス禁止法、個人情報保護法など）については FE Chapter 11 で扱います。

### 10. 科目 B の情報セキュリティ問題

科目 B の全 20 問のうち、4 問が情報セキュリティ分野から出題されます。プログラムの読解ではなく、ある企業の状況（ネットワーク構成、運用ルール、発生したインシデント）が文章で提示され、「どの対策が適切か」「原因は何か」を選ぶ **事例問題** の形式をとります。

解き方のコツ:

1. **設問を先に読む**: 何を答えるべきかを把握してから本文を読み始める
2. **本文の条件に従う**: 一般論として正しい対策であっても、本文の状況に合致しなければ不正解となる
3. **用語の意味を正確に押さえる**: この章で学んだ用語（多要素認証、DMZ、WAF など）の役割の違いが、そのまま選択肢を見分けるポイントになる

## 手を動かすパート

Python 標準ライブラリの `hashlib` を使うと、ハッシュ値が「1 文字違うだけでまったく別の値になる」ことを実際に確かめられます。

```python
>>> import hashlib
>>> hashlib.sha256("こんにちは".encode()).hexdigest()[:16]
'125aeadf27b0459b'
>>> hashlib.sha256("こんにちわ".encode()).hexdigest()[:16]
'f2d8a962c68276c6'
```

「は」と「わ」の 1 文字しか違わないにもかかわらず、出力されるハッシュ値はまったく似ていません。手元でも別の文字列に変えて試してみてください。また、Web 編 Ch6 の `code/` にある SQL インジェクション・XSS の再現スクリプトも、この章の復習に役立ちます。

## つまずきポイント

> [!CAUTION]
> セキュリティ分野では、似た用語の **取り違え** を狙う問題が大半を占める。特に次の 4 組は明確に区別できるようにしておくこと。

- <mark>**暗号化と署名で使う鍵**</mark>: 暗号化には「受信者の公開鍵」、署名には「送信者の秘密鍵」を使う
- <mark>**デジタル署名に機密性はない**</mark>: 証明できるのは本人性と改ざんの有無のみ
- **ファイアウォールと WAF**: アドレスとポート番号を見るのがファイアウォール、通信の中身を見るのが WAF
- **IDS と IPS**: 検知のみを行うか、遮断まで行うかの違い
- **多要素認証の「要素」**: パスワード ＋ 秘密の質問は、どちらも「知識」要素であるため多要素認証にはならない

## 重要な単語まとめ

| 用語 | 一言で言うと | 身近な実例 |
|---|---|---|
| **機密性・完全性・可用性** | 見せない・正しく保つ・使える状態を保つ | 情報漏えい・改ざん・サービス停止 |
| **脅威 / 脆弱性 / リスク** | 原因 / 弱点 / 損害が生じる可能性 | 古いままのソフトは脆弱性 |
| **リスクの回避・低減・移転・受容** | やめる・減らす・他者に任せる・受け入れる | サイバー保険は移転 |
| **ランサムウェア** | ファイルを暗号化して身代金を要求する | 病院や企業の被害報道 |
| **フィッシング** | 偽サイトへ誘導して情報を入力させる | 不在通知を装った SMS |
| **パスワードリスト攻撃** | 流出した ID とパスワードで不正ログインを試みる | パスワードの使い回しが原因 |
| **DDoS 攻撃** | 多数の端末から大量の通信を送りつけてサービスを止める | ボットネットが悪用される |
| **共通鍵暗号 / 公開鍵暗号** | 同じ鍵を使う / 公開鍵と秘密鍵のペアを使う | AES / RSA |
| **ハッシュ関数** | 固定長の値を算出する一方向の関数 | ダウンロードファイルの整合性確認 |
| **デジタル署名** | 送信者の秘密鍵で署名し、公開鍵で検証する | 本人性の証明と改ざん検知 |
| **認証局 / デジタル証明書 / PKI** | 公開鍵の所有者を保証する仕組み | ブラウザの鍵マーク |
| **多要素認証** | 知識・所有・生体のうち 2 つ以上を組み合わせる | パスワード ＋ スマホのコード |
| **シングルサインオン / パスキー** | 1 回のログインで複数サービスを利用 / 秘密鍵によるログイン | 「Google でログイン」 |
| **ファイアウォール / WAF / IPS** | アドレスで制限 / Web 攻撃を遮断 / 不正通信を遮断 | 多層防御 |
| **DMZ / VPN** | 公開サーバを置く緩衝地帯 / 暗号化された仮想専用線 | 在宅勤務での社内接続 |
| **ISMS / CSIRT** | 継続的なセキュリティ管理の仕組み / 事故対応チーム | ISO/IEC 27001 |
