## 本文

### 1. 情報セキュリティの 3 要素

| 要素 | 意味 | 損なわれる例 |
|---|---|---|
| **機密性**（Confidentiality） | 許可された人だけが見られる | 個人情報の漏えい |
| **完全性**（Integrity） | 内容が正しく、改ざんされていない | Web ページの改ざん |
| **可用性**（Availability） | 使いたいときに使える | DoS 攻撃でサービス停止 |

頭文字から **CIA** と呼ばれます。これに **真正性**（本物であること）、**責任追跡性**（誰がやったか後から追えること）、**否認防止**（やったことを後から否定させないこと）、**信頼性**（意図どおりに動くこと）を加えることもあります。

### 2. リスクの考え方

- **脅威**: 被害を引き起こす原因（攻撃者、ウイルス、地震、操作ミス）
- **脆弱性**: 脅威につけ込まれる弱点（パッチの当たっていないソフト、弱いパスワード）
- **リスク**: 脅威が脆弱性につけ込んで、損害が起きる可能性

リスクは「どのくらい起きやすいか × 起きたらどのくらい痛いか」で評価し、対応を決めます。

| リスク対応 | 中身 | 例 |
|---|---|---|
| **回避** | リスクの原因そのものをやめる | 危ないサービスの提供をやめる |
| **低減** | 起きにくく・被害を小さくする | ウイルス対策ソフト、バックアップ |
| **移転（共有）** | 他者に負担してもらう | サイバー保険、運用の外部委託 |
| **受容（保有）** | 小さいので受け入れる | 対策費の方が高くつく場合 |

### 3. マルウェア

悪意のあるソフトウェアの総称です。

| 種類 | 特徴 |
|---|---|
| **ウイルス** | 他のプログラムに寄生して増える |
| **ワーム** | 単独で、ネットワークを通じて自分をコピーして広がる |
| **トロイの木馬** | 便利なソフトのふりをして入り込み、裏で悪さをする |
| **ランサムウェア** | ファイルを暗号化して使えなくし、元に戻すための身代金を要求する。最近は「データを公開する」と二重に脅す手口も多い |
| **スパイウェア / キーロガー** | 利用者の情報や入力したキーを盗み取る |
| **ボット** | 感染した端末を外部から操れるようにする。大量のボットの集団（ボットネット）は DDoS 攻撃に使われる |
| **ルートキット** | 侵入の痕跡を隠すための道具一式 |

### 4. 代表的な攻撃手法

#### 人をだます攻撃

- **ソーシャルエンジニアリング**: 技術ではなく人の心理の隙を突く。電話で上司や担当者になりすましてパスワードを聞き出す、肩越しに画面をのぞく（ショルダーハッキング）、ゴミ箱から書類をあさる（トラッシング）など
- **フィッシング**: 本物そっくりの偽サイトやメールで、ID やパスワード、カード番号を入力させる。SMS を使うものはスミッシングと呼ばれる
- **標的型攻撃**: 特定の組織を狙い、取引先などを装ったメールでマルウェアを開かせる
- **ビジネスメール詐欺（BEC）**: 取引先や経営者になりすまして、偽の口座に送金させる

**実例**: 「荷物をお届けしましたが不在でした」「アカウントが停止されます」という SMS のリンクは、ほぼフィッシングです。正規のアプリやブックマークから公式サイトを開いて確かめるのが基本の対処です。

#### パスワードを狙う攻撃

| 攻撃 | 中身 | 効く対策 |
|---|---|---|
| **総当たり（ブルートフォース）** | 1 つのアカウントに、全パターンを順に試す | 一定回数の失敗でロック |
| **辞書攻撃** | よく使われる単語や文字列を順に試す | 推測されにくいパスワード |
| **リバースブルートフォース** | よくあるパスワード 1 つを固定し、ID の方を次々に変えて試す | ロックが効きにくい。多要素認証 |
| **パスワードリスト攻撃** | 他のサービスから漏れた ID とパスワードの組をそのまま試す | <mark>**パスワードを使い回さない**</mark>、多要素認証 |

#### サービスや通信を狙う攻撃

- **DoS / DDoS 攻撃**: 大量の通信を送りつけて、サービスを止める（可用性を損なう）。多数の端末から一斉に行うのが DDoS
- **中間者攻撃**: 通信の間に割り込んで、盗み見たり書き換えたりする。TLS で防ぐ（Web 編 Ch3）
- **DNS キャッシュポイズニング**: DNS サーバのキャッシュに偽の情報を覚えさせ、偽サイトへ誘導する
- **ゼロデイ攻撃**: 脆弱性が見つかってから、修正プログラム（パッチ）が出る前に突く攻撃
- **SQL インジェクション・XSS・CSRF**: Web アプリへの攻撃（Web 編 Ch6 で再現済み）
- **ディレクトリトラバーサル**: `../` を使ってファイルのパスをさかのぼり、公開されていないファイルを読む
- **サプライチェーン攻撃**: 防御の固い本命ではなく、取引先や使っているソフトウェア部品を経由して侵入する

### 5. 暗号

暗号化前の文を **平文**、暗号化した文を **暗号文**、暗号化と復号に使う値を **鍵** と呼びます。

#### 共通鍵暗号と公開鍵暗号

| | 共通鍵暗号 | 公開鍵暗号 |
|---|---|---|
| 鍵 | 暗号化と復号に **同じ鍵** を使う | **公開鍵** と **秘密鍵** のペアを使う |
| 速さ | 速い | 遅い |
| 困りごと | 鍵を相手に安全に渡す方法が必要 | 処理が重い |
| 代表 | AES | RSA、楕円曲線暗号 |
| n 人が互いに通信するのに必要な鍵の数 | n(n − 1) ÷ 2 個 | 2n 個（1 人 1 ペア） |

> [!CAUTION]
> 公開鍵暗号で秘密の文書を送るときは、<mark>**受信者の公開鍵で暗号化し、受信者が自分の秘密鍵で復号する**</mark>。一方、次に出てくるデジタル署名では **送信者の秘密鍵で署名し、受信者が送信者の公開鍵で確かめる**。「誰の」「どちらの」鍵かの組合せは毎回のように出る。

**例題**: 10 人が互いに秘密の通信をするとき、共通鍵暗号なら 10 × 9 ÷ 2 ＝ **45 個**、公開鍵暗号なら 10 × 2 ＝ **20 個** の鍵が必要です。人数が増えるほど差が開きます。

#### ハイブリッド暗号

実際の通信では、両方のいいところを組み合わせます。**公開鍵暗号で共通鍵を安全に受け渡し、本体のデータは速い共通鍵暗号で暗号化する**。Web 編 Ch3 の TLS ハンドシェイクで「共通鍵を作る」とあったのは、この流れです。

#### ハッシュ関数

任意の長さのデータから、決まった長さの値（**ハッシュ値**）を作る関数です。SHA-256 などがあります。

- 同じデータからは必ず同じハッシュ値が出る
- 1 文字でも変わると、ハッシュ値がまったく違うものになる
- ハッシュ値から元のデータには戻せない（一方向性）

ダウンロードしたファイルが壊れたり改ざんされたりしていないかを確かめる（完全性の確認）のに使います。パスワードの保存では、専用のハッシュ関数（bcrypt、Argon2 など）を使います（Web 編 Ch6）。

### 6. デジタル署名と PKI

#### デジタル署名

「この文書は確かに本人が作り、途中で改ざんされていない」ことを確かめる仕組みです。

1. 送信者は文書のハッシュ値を作り、それを **送信者の秘密鍵** で暗号化する（これが署名）
2. 文書と署名を送る
3. 受信者は署名を **送信者の公開鍵** で復号し、自分で計算した文書のハッシュ値と比べる
4. 一致すれば「本人が作った（秘密鍵を持っているのは本人だけ）」「改ざんされていない」と分かる

<mark>**デジタル署名で確かめられるのは「本人であること」と「改ざんされていないこと」**</mark>。文書の中身を隠す（機密性）機能はありません。

#### PKI と認証局

「その公開鍵が本当にその人（そのサイト）のものか」を保証するのが **認証局（CA）** で、公開鍵に認証局が署名したものが **デジタル証明書** です。この仕組み全体を **PKI（公開鍵基盤）** と呼びます。

**実例**: ブラウザの鍵マークをクリックして見られる証明書がこれです（Web 編 Ch3）。Let's Encrypt などの認証局が「この公開鍵は確かに example.com のものだ」と署名しています。有効期限内に失効させた証明書の一覧は **CRL**（証明書失効リスト）で確認します。

### 7. 利用者認証

本人確認の方法は、大きく 3 種類（**認証の 3 要素**）に分かれます。

| 要素 | 例 |
|---|---|
| **知識**（知っているもの） | パスワード、暗証番号、秘密の質問 |
| **所有**（持っているもの） | スマホ、IC カード、ハードウェアキー |
| **生体**（本人の身体の特徴） | 指紋、顔、静脈、虹彩 |

- **多要素認証**: 異なる要素を 2 つ以上組み合わせる。「パスワード ＋ スマホに届くコード」など。パスワードを 2 回聞くのは同じ要素なので多要素ではない
- **ワンタイムパスワード**: 1 回しか使えないパスワード。認証アプリに 30 秒ごとに表示される数字など
- **シングルサインオン（SSO）**: 1 回の認証で複数のサービスを使えるようにする。「Google でログイン」など
- **CAPTCHA**: ゆがんだ文字や画像の選択で、相手が人間かプログラムかを見分ける
- **パスキー**: パスワードの代わりに、端末に保存した秘密鍵と生体認証などでログインする方式。偽サイトでは使えないのでフィッシングに強い

生体認証では、本人なのに拒否してしまう率（**本人拒否率**）と、他人を受け入れてしまう率（**他人受入率**）がトレードオフになります。

### 8. 技術的な対策

| 対策 | 役割 |
|---|---|
| **ファイアウォール** | IP アドレスやポート番号を見て、通してよい通信だけを通す（パケットフィルタリング） |
| **WAF** | Web アプリへの通信の **中身** を見て、SQL インジェクションや XSS のような攻撃のパターンを止める |
| **IDS / IPS** | 不正な通信を検知する（IDS）／検知して遮断までする（IPS） |
| **DMZ** | 社内ネットワークとインターネットの間に置く緩衝地帯。外部に公開する Web サーバなどを置き、侵入されても社内には入られにくくする |
| **VPN** | インターネット上に暗号化した仮想的な専用線を作る。自宅から会社のネットワークに入るなど |
| **プロキシサーバ** | 社内の端末の代わりに外部と通信する中継役。閲覧の制限やログ取得に使う |
| **検疫ネットワーク** | 社外から持ち込んだ PC を、安全を確認するまで隔離されたネットワークにつなぐ |
| **ペネトレーションテスト** | 実際に攻撃してみて弱点を探す検査 |
| **デジタルフォレンジックス** | 事件のあと、証拠となるデータを保全・分析する |

最近は「社内のネットワークは安全」という前提を捨て、すべてのアクセスを毎回確かめる **ゼロトラスト** という考え方も広がっています。

### 9. 組織としての対策

- **情報セキュリティポリシー**: 組織としての方針（基本方針・対策基準・実施手順）
- **ISMS**: 情報セキュリティを継続的に管理する仕組み。**PDCA サイクル**（計画・実行・点検・改善）で回す。国際規格は ISO/IEC 27001、日本では JIS Q 27001
- **CSIRT**: セキュリティ事故（インシデント）が起きたときに対応する組織内のチーム
- **SOC**: ネットワークや機器を 24 時間監視し、攻撃を検知・分析する組織
- **IPA の「情報セキュリティ 10 大脅威」**: その年に社会的影響の大きかった脅威を IPA が毎年発表している。ランサムウェアや標的型攻撃が上位の常連

関連する法律（不正アクセス禁止法、個人情報保護法など）は FE Chapter 11 で扱います。

### 10. 科目 B の情報セキュリティ問題

科目 B の 20 問のうち 4 問が情報セキュリティです。プログラムではなく、ある会社の状況（ネットワーク構成、運用ルール、起きた事件）が文章で示され、「どの対策が適切か」「原因は何か」を選ぶ **事例問題** の形をとります。

解き方のコツ:

1. **設問を先に読む**: 何を答えればよいかを決めてから本文を読む
2. **本文の条件に従う**: 一般論として正しい対策でも、本文の状況に合わなければ不正解
3. **用語の意味を正確に**: この章の用語（多要素認証、DMZ、WAF など）の違いがそのまま選択肢の差になる

## 手を動かすパート

Python 標準の `hashlib` で、ハッシュ値が「1 文字の違いでまったく変わる」ことを確かめられます。

```python
>>> import hashlib
>>> hashlib.sha256("こんにちは".encode()).hexdigest()[:16]
'125aeadf27b0459b'
>>> hashlib.sha256("こんにちわ".encode()).hexdigest()[:16]
'f2d8a962c68276c6'
```

「は」と「わ」の 1 文字しか違わないのに、ハッシュ値はまったく似ていません。自分でも別の文字列で試してみてください。Web 編 Ch6 の `code/` にある SQL インジェクション・XSS の再現スクリプトも、この章の復習になります。

## つまずきポイント

> [!CAUTION]
> セキュリティは用語の **取り違え** を狙う問題がほとんど。特に次の 4 組は区別できるようにしておく。

- <mark>**暗号化と署名で使う鍵**</mark>: 暗号化は「受信者の公開鍵」、署名は「送信者の秘密鍵」
- <mark>**デジタル署名に機密性はない**</mark>: 分かるのは本人性と改ざんの有無だけ
- **ファイアウォールと WAF**: アドレスとポートを見るのがファイアウォール、通信の中身を見るのが WAF
- **IDS と IPS**: 検知だけか、遮断までするか
- **多要素認証の「要素」**: パスワード ＋ 秘密の質問は、どちらも知識なので多要素ではない

## 重要な単語まとめ

| 用語 | 一言で言うと | 身近な実例 |
|---|---|---|
| **機密性・完全性・可用性** | 見せない・正しく保つ・使える状態を保つ | 情報漏えい・改ざん・サービス停止 |
| **脅威 / 脆弱性 / リスク** | 原因 / 弱点 / 損害が起きる可能性 | 古いままのソフトは脆弱性 |
| **リスクの回避・低減・移転・受容** | やめる・減らす・人に任せる・受け入れる | サイバー保険は移転 |
| **ランサムウェア** | ファイルを暗号化して身代金を要求 | 病院や企業の被害が報道される |
| **フィッシング** | 偽サイトで情報を入力させる | 不在通知を装った SMS |
| **パスワードリスト攻撃** | 漏れた ID とパスワードを使い回す | パスワードの使い回しが原因 |
| **DDoS 攻撃** | 多数の端末から通信を送りつけてサービスを止める | ボットネットが使われる |
| **共通鍵暗号 / 公開鍵暗号** | 同じ鍵 / 公開鍵と秘密鍵のペア | AES / RSA |
| **ハッシュ関数** | 決まった長さの値を作る一方向の関数 | ダウンロードファイルの確認 |
| **デジタル署名** | 送信者の秘密鍵で署名し、公開鍵で確かめる | 本人性と改ざん検知 |
| **認証局 / デジタル証明書 / PKI** | 公開鍵の持ち主を保証する仕組み | ブラウザの鍵マーク |
| **多要素認証** | 知識・所有・生体のうち 2 つ以上 | パスワード ＋ スマホのコード |
| **シングルサインオン / パスキー** | 1 回のログインで複数サービス / 秘密鍵でのログイン | 「Google でログイン」 |
| **ファイアウォール / WAF / IPS** | アドレスで遮断 / Web 攻撃を遮断 / 不正侵入を遮断 | 多層の防御 |
| **DMZ / VPN** | 公開サーバを置く緩衝地帯 / 暗号化した仮想専用線 | 在宅勤務の社内接続 |
| **ISMS / CSIRT** | 継続的なセキュリティ管理の仕組み / 事故対応チーム | ISO/IEC 27001 |
