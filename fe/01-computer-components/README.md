# FE Chapter 1: コンピュータ構成要素

> Status: 完了

## この章で学ぶこと

- コンピュータを形づくる **5 大装置** と、その中心にある CPU の仕事
- CPU の速さを表す数字（クロック周波数・CPI・MIPS）の計算
- CPU を速くする工夫（パイプライン・マルチコアなど）
- メモリの種類と **記憶階層**、キャッシュメモリの計算
- HDD / SSD の違いと、HDD のアクセス時間の計算
- USB・Bluetooth など入出力インタフェース

## 前提知識

- 特になし。自分のパソコンやスマホの「スペック表」（CPU・メモリ・ストレージ）を一度見たことがあれば十分です。

## 本文

### 1. 5 大装置

コンピュータは、役割で分けると次の 5 つの装置でできています。

| 装置 | 役割 | 身近な例 |
|---|---|---|
| **入力装置** | 外からデータを取り込む | キーボード、マウス、スマホのタッチパネル、カメラ |
| **出力装置** | 結果を外へ出す | ディスプレイ、プリンタ、スピーカー |
| **記憶装置** | データやプログラムを覚えておく | メモリ（主記憶）、SSD・HDD（補助記憶） |
| **演算装置** | 計算する | CPU の中にある |
| **制御装置** | ほかの装置に指示を出す | CPU の中にある |

<mark>**演算装置と制御装置をまとめたものが CPU（中央処理装置）**</mark> です。CPU は「プロセッサ」とも呼ばれます。

**実例**: スマホの仕様表に「SoC: ○○」と書かれていることがあります。SoC（System on a Chip）は、CPU に加えて GPU（画像処理）や通信機能まで 1 枚のチップに載せたものです。小さな筐体に全部を詰めるための工夫です。

### 2. プログラム内蔵方式と命令の実行

いまのコンピュータは、<mark>**プログラムもデータと同じように主記憶（メモリ）に置いておき、CPU がそれを 1 命令ずつ読み出して実行する**</mark> という方式で動いています。これを **プログラム内蔵方式**（ノイマン型）と呼びます。

CPU が 1 つの命令を処理する流れは、ざっくり次の繰り返しです。

1. **命令の取り出し（フェッチ）**: 次に実行する命令をメモリから読む
2. **命令の解読（デコード）**: 何をする命令か調べる
3. **オペランドの読み出し**: 計算に使うデータを用意する
4. **実行**: 計算する
5. **結果の書き込み**: 結果をレジスタやメモリに書く

この流れの中で使われる、CPU 内部の小さな記憶場所が **レジスタ** です。

| レジスタ | 役割 |
|---|---|
| **プログラムカウンタ** | 次に実行する命令が置かれたメモリの番地（アドレス）を覚えておく |
| **命令レジスタ** | いま取り出した命令を一時的に置く |
| **汎用レジスタ / アキュムレータ** | 計算途中の値を置く |

**実例**: 動画を見ながら「今どこまで再生したか」を覚えているシークバーの位置が、プログラムカウンタのイメージに近いです。1 命令終わるごとに「次はここ」と進んでいきます。

#### アドレス指定方式

命令の中には「どこのデータを使うか」を指す部分（アドレス部）があります。その指し方にはいくつか種類があり、科目 A の計算問題で出題されます。

| 方式 | アドレス部の値の意味 |
|---|---|
| **即値** | 値そのもの |
| **直接** | データが置かれている番地 |
| **間接** | 「データの番地」が書かれている番地（2 段階でたどる） |
| **インデックス** | アドレス部の値 ＋ インデックスレジスタの値 が番地 |
| **ベース** | アドレス部の値 ＋ ベースレジスタの値 が番地 |
| **相対** | アドレス部の値 ＋ プログラムカウンタの値 が番地 |

### 3. CPU の性能を表す数字

#### クロック周波数

CPU は、一定のリズム（クロック）に合わせて動きます。1 秒間のリズムの回数が **クロック周波数** で、単位は Hz（ヘルツ）です。`3 GHz` なら 1 秒間に 30 億回です。

#### CPI と MIPS

- **CPI（Cycles Per Instruction）**: 1 命令を実行するのに、平均で何クロックかかるか
- **MIPS（Million Instructions Per Second）**: 1 秒間に何百万命令を実行できるか

> [!CAUTION]
> 計算問題の基本形は <mark>**1 秒間に実行できる命令数 ＝ クロック周波数 ÷ CPI**</mark> です。単位をそろえ忘れるのがいちばん多いミスです。G（ギガ）＝ 10⁹、M（メガ）＝ 10⁶、ミリ ＝ 10⁻³、マイクロ ＝ 10⁻⁶、ナノ ＝ 10⁻⁹ をまず書き出してから計算します。

**例題**: クロック周波数 2 GHz、CPI が 4 の CPU は何 MIPS か。

- 1 秒間の命令数 ＝ 2 × 10⁹ ÷ 4 ＝ 5 × 10⁸ 命令
- MIPS に直すと 5 × 10⁸ ÷ 10⁶ ＝ **500 MIPS**

逆に「1 命令あたりの平均実行時間」は 1 ÷ (5 × 10⁸) ＝ 2 × 10⁻⁹ 秒 ＝ **2 ナノ秒** です。

### 4. CPU を速くする工夫

| 工夫 | 中身 | たとえ |
|---|---|---|
| **パイプライン** | 命令の各段階（取り出し・解読・実行…）をずらして重ねて処理する | 洗濯・乾燥・たたみを、1 回分ずつずらして並行に進める |
| **スーパースカラ** | パイプラインを複数本持ち、同時に複数の命令を流す | 洗濯機を 2 台にする |
| **マルチコア** | 1 つの CPU チップに処理の核（コア）を複数載せる | 調理人を複数人にする |
| **GPU** | 単純な計算を大量に同時に行うのが得意なプロセッサ | 画像処理、ゲーム、AI の学習 |

パイプラインでは、分岐命令（if 文など）で次に実行する命令が変わると、先読みしていた分が無駄になります。これを **パイプラインハザード** と呼びます。

**実例**: パソコンの仕様に「8 コア 16 スレッド」と書かれているのは、物理的なコアが 8 個あり、1 コアが 2 つの処理の流れ（スレッド）を同時に扱えるという意味です。

### 5. メモリ（主記憶）と記憶階層

#### 半導体メモリの種類

| 種類 | 電源を切ると | 特徴・用途 |
|---|---|---|
| **DRAM** | 消える（揮発性） | 安くて大容量。定期的な再書き込み（リフレッシュ）が必要。パソコンの「メモリ 16GB」はこれ |
| **SRAM** | 消える（揮発性） | 高速だが高価。キャッシュメモリに使う |
| **フラッシュメモリ** | 消えない（不揮発性） | SSD、USB メモリ、SD カード、スマホのストレージ |
| **ROM** | 消えない | 読み出し専用（書き換えできる種類もある）。機器の起動用プログラムなど |

#### 記憶階層

速い記憶装置ほど高価で容量が小さいため、速さの違うものを段階的に組み合わせて使います。

```
速い・小さい・高い
  レジスタ
  キャッシュメモリ（L1 → L2 → L3）
  主記憶（DRAM）
  SSD / HDD（補助記憶）
遅い・大きい・安い
```

#### キャッシュメモリと実効アクセス時間

CPU は主記憶に比べて圧倒的に速いため、主記憶を待っていると CPU が遊んでしまいます。そこで、よく使うデータを CPU の近くにある高速な **キャッシュメモリ** に写しておきます。

欲しいデータがキャッシュにあった割合を **ヒット率** と呼び、平均のアクセス時間（実効アクセス時間）は次の式で求めます。

```
実効アクセス時間 ＝ キャッシュのアクセス時間 × ヒット率
                 ＋ 主記憶のアクセス時間 × (1 − ヒット率)
```

**例題**: キャッシュ 10 ナノ秒、主記憶 60 ナノ秒、ヒット率 90% のとき、

10 × 0.9 ＋ 60 × 0.1 ＝ 9 ＋ 6 ＝ **15 ナノ秒**

**実例**: ブラウザのキャッシュも同じ発想です。一度見たサイトの画像を手元に保存しておき、次に開いたときはネットワーク越しに取りに行きません。Web 編 Ch3 の `Cache-Control` ヘッダーの話とつながります。

#### キャッシュへの書き込み方式

- **ライトスルー**: キャッシュと主記憶に同時に書く。内容は常に一致するが遅い
- **ライトバック**: まずキャッシュにだけ書き、追い出されるときに主記憶へ書く。速いが管理が複雑

### 6. 補助記憶装置

#### HDD と SSD

| | HDD | SSD |
|---|---|---|
| しくみ | 回転する円盤（磁気ディスク）に磁気で記録し、ヘッドを動かして読み書き | フラッシュメモリに電気的に記録 |
| 速さ | 遅い（物理的に動く） | 速い |
| 衝撃 | 弱い | 強い |
| 容量あたりの価格 | 安い | 高め |

#### HDD のアクセス時間

HDD でデータを読むには、①ヘッドを目的のトラック（同心円）まで動かし、②目的の場所が回ってくるのを待ち、③データを読み取る、という 3 段階があります。

```
平均アクセス時間 ＝ 平均シーク時間 ＋ 平均回転待ち時間 ＋ データ転送時間
平均回転待ち時間 ＝ 1 回転にかかる時間 ÷ 2
```

**例題**: 毎分 6,000 回転の HDD の平均回転待ち時間は？

- 1 回転の時間 ＝ 60 秒 ÷ 6,000 ＝ 0.01 秒 ＝ 10 ミリ秒
- 平均回転待ち ＝ 10 ÷ 2 ＝ **5 ミリ秒**

「平均すると半周待つ」ので 2 で割ります。

#### 断片化（フラグメンテーション）

ファイルの書き込みと削除を繰り返すと、1 つのファイルがディスクのあちこちに分かれて置かれ、HDD では読み出しが遅くなります。これを並べ直すのが **デフラグ** です。SSD は位置による速度差がほとんどないため、デフラグは基本的に不要です。

### 7. 入出力インタフェース

| 種類 | 特徴 | 身近な例 |
|---|---|---|
| **USB** | 汎用の有線接続。電源供給もできる。USB Type-C は向きを気にせず挿せる | マウス、充電ケーブル |
| **HDMI** | 映像と音声をまとめて送る | テレビとゲーム機・PC |
| **Bluetooth** | 近距離の無線接続 | ワイヤレスイヤホン |
| **NFC** | 数 cm の距離で通信 | 交通系 IC カード、スマホのタッチ決済 |
| **IrDA** | 赤外線通信 | 昔の携帯電話の赤外線通信 |

USB には **ホットプラグ**（電源を入れたまま抜き挿しできる）や **プラグアンドプレイ**（挿すだけで OS が認識して設定する）という性質があります。

#### デバイスドライバ

周辺機器を OS から使えるようにする小さなソフトウェアが **デバイスドライバ** です。プリンタを初めてつないだときに「ドライバをインストールしています」と出るのがこれです。

`code/cpu_calc.py` に、この章の 3 つの計算（MIPS・実効アクセス時間・HDD の回転待ち）を Python で確かめるスクリプトを置いてあります。標準ライブラリだけで動きます。

```powershell

```

## つまずきポイント

> [!CAUTION]
> 科目 A の計算問題で **ほぼ確実に一度は踏む** 罠のリストです。答えの選択肢には「単位を間違えたときの値」が必ず混ざっているので注意してください。

- <mark>**単位の換算を最初にやる**</mark>: GHz とナノ秒、分と秒、ビットとバイト（1 バイト ＝ 8 ビット）。計算に入る前に全部そろえる
- <mark>**回転待ちは「半周」**</mark>: 平均回転待ち時間は 1 回転の時間の半分。2 で割り忘れるのが定番のミス
- **キャッシュのヒット率と「ミス率」**: 問題文がミス率（＝ 1 − ヒット率）で書かれていることがある
- **DRAM と SRAM の取り違え**: 主記憶 ＝ DRAM（安い・リフレッシュ要）、キャッシュ ＝ SRAM（速い・高い）
- **フラッシュメモリは不揮発**: 「メモリ」という名前だが電源を切っても消えない。主記憶の DRAM とは別物
