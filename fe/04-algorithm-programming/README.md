## 本文

### 1. アルゴリズムとは

**アルゴリズム** とは、「問題を解くための、手順が決まった処理の流れ」のことです。料理のレシピのように、誰が実行しても同じ結果になるよう、曖昧さなく書かれた手順を指します。

どんなに複雑なプログラムも、次の 3 つの基本制御構造の組み合わせで記述できます（**構造化定理**）。

| 基本制御構造 | 意味 | Python で書くと |
|---|---|---|
| **順次** | 上から順に実行する | ただ行を並べる |
| **選択** | 条件によって処理を分ける | `if` / `elif` / `else` |
| **繰返し** | 条件を満たす間、処理をくり返す | `while` / `for` |

#### 流れ図（フローチャート）

手順を図で表したものです。端子（角の丸い長方形）で始まりと終わり、長方形で処理、ひし形で判断、台形を上下に組み合わせた記号で繰返しの範囲（ループ端）を表します。

**実例**: 「改札を通る」という手順を流れ図にすると、「IC カードをタッチ → 残高は運賃以上か？（判断）→ はいなら扉が開く／いいえなら扉が閉じてチャージを促す」という選択の構造になります。

### 2. 変数と配列

- **変数**: 値を入れておく名前付きの箱。`total ← 0` のように値を入れる（代入）
- **配列**: 同じ型の値を番号付きで並べたもの。番号を **要素番号（添字）** と呼ぶ

> [!CAUTION]
> <mark>**Python のリストは要素番号が 0 から始まるが、FE の擬似言語は問題文で「配列の要素番号は 1 から始まる」と指定されることが多い**</mark>。Python の感覚で読むと 1 つずれてしまう。科目 B の問題では、まず問題文の前提で要素番号の始まりを確認する。

2 次元配列は「表」のイメージです。`board[行][列]` のように 2 つの番号で要素を指定します。

### 3. データ構造

#### リスト（連結リスト）

各要素が「値」と「次の要素の場所（ポインタ）」を持ち、数珠つなぎになったデータ構造です。

- 途中への **挿入・削除が速い**（ポインタを付け替えるだけで済む）
- 何番目かを指定して取り出すには先頭からたどる必要があり、遅い

配列はその逆で、何番目かの要素を取り出すのは速いですが、途中へ挿入するにはそれ以降の要素をすべてずらす必要があります。

#### スタックとキュー

| | スタック | キュー |
|---|---|---|
| 取り出す順番 | <mark>**後に入れたものから（LIFO: Last In First Out）**</mark> | <mark>**先に入れたものから（FIFO: First In First Out）**</mark> |
| 入れる / 出す操作 | push / pop | enqueue / dequeue |
| 身近な例 | 積み重ねた皿、ブラウザの「戻る」ボタン | レジの行列、プリンタの印刷待ち |

**実例**: ブラウザで A → B → C とページを進むと、履歴が A・B・C の順に積まれます。「戻る」を押すと最後に積んだ C が取り出されて B に戻ります。これがスタックです。

#### 木構造

1 つの根（ルート）から枝分かれしていくデータ構造です。ファイルのフォルダ構造が典型例です。

- **2 分木**: 各節（ノード）の子が 2 つ以下の木
- **2 分探索木**: 「左の子孫 ＜ 自分 ＜ 右の子孫」が常に成り立つ 2 分木。大小比較で左右に進むだけで目的の値にたどり着ける
- **ヒープ**: 「親は子より常に小さい（または大きい）」が成り立つ木。最小値（最大値）をすぐ取り出せる

#### 木のたどり方

| 方法 | 順番 |
|---|---|
| **先行順（行きがけ順）** | 自分 → 左 → 右 |
| **中間順（通りがけ順）** | 左 → 自分 → 右（2 分探索木なら小さい順に並ぶ） |
| **後行順（帰りがけ順）** | 左 → 右 → 自分 |

#### グラフ

点（ノード）と線（エッジ）で「つながり」を表す構造です。電車の路線図や SNS のフォロー関係がこれにあたります。

### 4. 探索（サーチ）

たくさんのデータの中から目的の値を探す方法です。

#### 線形探索

先頭から 1 つずつ順に調べます。データが並んでいなくても使えますが、n 個のデータがある場合は最悪 n 回比較します。

**番兵法**: 探す値をデータの末尾にわざと置いておくと、「必ず見つかる」ため、毎回の「最後まで到達したか？」という判定を省けます。

#### 2 分探索

<mark>**データが小さい順（または大きい順）に並んでいることが前提です**</mark>。真ん中の値と比べて、探す値が小さければ左半分、大きければ右半分に絞り込む操作をくり返します。

```
探す値: 37
[ 3, 8, 15, 21, 37, 42, 56, 70 ]
  真ん中は 21（4 番目）→ 37 の方が大きい → 右半分へ
[ 37, 42, 56, 70 ]
  真ん中は 42 → 37 の方が小さい → 左半分へ
[ 37 ] → 見つかった
```

1 回比べるごとに候補が半分になるため、比較回数は最大でも約 log₂n 回です。1,000 件なら約 10 回、100 万件でも約 20 回で済みます。

**実例**: 辞書で単語を引くとき、最初のページから順にめくる人はいません。真ん中あたりを開いて「もっと前か後か」で絞り込んでいきます。それが 2 分探索です。

### 5. 整列（ソート）

| 方法 | 考え方 | 計算量の目安 |
|---|---|---|
| **選択ソート** | 残りの中から最小値を探して先頭と交換する操作をくり返す | O(n²) |
| **バブルソート** | 隣どうしを比べて逆順なら交換する操作を端から端までくり返す | O(n²) |
| **挿入ソート** | 整列済みの部分に、次の 1 個を正しい位置へ差し込む | O(n²)（ほぼ整列済みなら速い） |
| **クイックソート** | 基準値（ピボット）より小さいグループと大きいグループに分け、それぞれを同じ方法で整列する | 平均 O(n log n) |
| **マージソート** | 半分に分けてそれぞれを整列し、2 つを合わせる（マージ） | O(n log n) |
| **ヒープソート** | ヒープを作って最小（最大）の値を順に取り出す | O(n log n) |

#### 計算量（オーダー）

データ量 n が増えたとき、処理時間がどのくらいの勢いで増えるかを **O 記法** で表します。

| オーダー | n が 10 倍になると | 例 |
|---|---|---|
| O(1) | 変わらない | 配列の要素番号を指定して取り出す |
| O(log n) | 少しだけ増える | 2 分探索 |
| O(n) | 10 倍 | 線形探索 |
| O(n log n) | 10 倍強 | クイックソート（平均）、マージソート |
| O(n²) | 100 倍 | 選択ソート、バブルソート |

**実例**: 1 万件のデータを O(n²) のソートで並べると 1 億回程度の比較が必要ですが、O(n log n) なら十数万回程度で済みます。データが増えるほど差が開きます。Python の `sorted()` は O(n log n) の方法（Timsort）を使っています。

### 6. 再帰

関数の中で **自分自身を呼び出す** ことを **再帰** と呼びます。必ず「これ以上呼び出さない終了条件」を記述します。

```python
def factorial(n):
    if n <= 1:          # 終わりの条件
        return 1
    return n * factorial(n - 1)   # 自分自身を呼ぶ

factorial(4)  # 4 × 3 × 2 × 1 ＝ 24
```

呼び出しの流れを書くと、`factorial(4)` → `4 × factorial(3)` → `4 × 3 × factorial(2)` → `4 × 3 × 2 × factorial(1)` → `4 × 3 × 2 × 1` と展開されます。

**実例**: 合わせ鏡の中の鏡や、マトリョーシカ人形のようなものです。「中に同じ形のものが入っていて、いちばん小さいものに到達したら終わり」という構造が再帰です。

### 7. プログラム言語の基本と擬似言語

#### プログラム言語の種類

| 種類 | 例 | 用途 |
|---|---|---|
| 手続き型 | C | OS や組込み機器 |
| オブジェクト指向 | Java、C#、Python | 業務システム、アプリ |
| スクリプト言語 | Python、JavaScript | 自動化、Web |
| マークアップ言語 | HTML、XML | 文書の構造（プログラム言語ではない） |

#### 擬似言語

科目 B では、特定の言語に依存しない **擬似言語** でプログラムが書かれます。Python と対応させると次のとおりです（詳しい記述形式は FE Chapter 12）。

| 擬似言語 | Python |
|---|---|
| `整数型: x` | （型の宣言は不要） |
| `x ← 5` | `x = 5` |
| `if (x > 0)` … `endif` | `if x > 0:` |
| `while (i ≦ n)` … `endwhile` | `while i <= n:` |
| `for (i を 1 から n まで 1 ずつ増やす)` … `endfor` | `for i in range(1, n + 1):` |
| `x mod 3` | `x % 3` |
| `return x` | `return x` |

## つまずきポイント

> [!CAUTION]
> 科目 A・B の両方で **毎回のように狙われる** 罠のリスト。

- <mark>**2 分探索は整列済みが前提**</mark>: 並んでいないデータには使えない。選択肢の「どんなデータにも使える」は誤り
- **スタックとキューの取り違え**: スタックは後入れ先出し（LIFO）、キューは先入れ先出し（FIFO）
- **要素番号の始まり**: 擬似言語では問題文で確認する。Python の 0 始まりの感覚のまま読まない
- **`for` の範囲の端**: 「1 から n まで」は n を **含む**。Python の `range(1, n)` は n を含まないので `range(1, n + 1)` と書く
- **再帰の終わりの条件**: これがないと無限に呼び出し続ける。トレースでは「どこで止まるか」を最初に探す
