## 本文

### 1. プロジェクトマネジメント

#### EVM の指標

FE で見た PV（計画価値）・EV（出来高）・AC（実コスト）から、比率を計算します。

| 指標 | 式 | 1 より小さいと |
|---|---|---|
| **SPI**（スケジュール効率指数） | EV ÷ PV | 予定より **遅れている** |
| **CPI**（コスト効率指数） | EV ÷ AC | 予算を **超えている** |

完成までにかかる総コストの見込み（**EAC**）は、今の効率が続くと考えるなら **BAC（総予算） ÷ CPI** で求めます。

**例題**: 総予算 1,000 万円、現時点で PV 400 万円・EV 300 万円・AC 400 万円。

- SPI ＝ 300 ÷ 400 ＝ 0.75（遅れている）
- CPI ＝ 300 ÷ 400 ＝ 0.75（予算超過）
- EAC ＝ 1,000 ÷ 0.75 ≒ **1,333 万円**

> [!CAUTION]
> <mark>**SPI も CPI も分子は EV（出来高）**</mark>。分母が PV ならスケジュール、AC ならコスト。SV（＝ EV − PV）や CV（＝ EV − AC）のような差で聞かれる場合も、引くのは常に EV から。PV と AC を直接比べる選択肢はひっかけ。

#### リスクの定量評価

リスクの大きさを **発生確率 × 影響額** の期待値（EMV）で比べます。確率 20% で 500 万円の損失なら、期待値は 100 万円。対策費が 100 万円より安ければ、対策する価値がある、と考えます。

#### PMBOK の改訂

PMBOK は第 7 版（2021 年）で、作業の手順（プロセス）中心の書き方から、**原理・原則** と **パフォーマンス領域**（ステークホルダ、チーム、開発アプローチ、計画、作業、デリバリー、測定、不確かさ）中心の書き方に大きく変わりました。2025 年には第 8 版も出ています。試験では、どちらの考え方の用語も出ることがあります。

### 2. サービスマネジメント

#### 管理の対象

| 管理 | 中身 |
|---|---|
| **可用性管理** | サービスが使える状態を保つ。稼働率、MTBF、MTTR を管理する |
| **容量・能力管理** | 今と将来の利用量に対して、CPU・ストレージ・回線が足りるかを管理する |
| **サービス継続管理** | 災害など大きな障害のときに、決めた時間内にサービスを再開できるようにする |
| **情報セキュリティ管理** | サービスに関わる情報の機密性・完全性・可用性を守る |

#### RTO と RPO

| 指標 | 意味 | 例 |
|---|---|---|
| **RTO**（目標復旧時間） | 止まってから **いつまでに** 再開するか | 4 時間以内に再開する |
| **RPO**（目標復旧時点） | **どの時点の** データまで戻せればよいか | 前日の 24 時時点のデータまで |

RPO を「1 時間前」にしたければ、少なくとも 1 時間ごとにバックアップや複製を取る必要があります。

**実例**: スマホのクラウドバックアップが「毎晩」なら、RPO は最大でほぼ 1 日分。昼に撮った写真は、夜のバックアップ前に壊れたら戻りません。

#### ITIL 4

ITIL は 2019 年の第 4 版で、サービスを「価値を共に作るもの」と捉える **サービスバリューシステム** の考え方に変わり、管理の単位も「プロセス」から「プラクティス」と呼ぶようになりました。インシデント管理・問題管理・変更管理などの中身は FE で学んだものと同じです。

### 3. システム監査

#### 監査の手続

| 手続 | 中身 |
|---|---|
| **インタビュー** | 担当者に話を聞く |
| **ドキュメントレビュー** | 規程・設計書・記録を読む |
| **突合・照合** | 2 つの記録が一致しているかを比べる |
| **観察（現地調査）** | 実際に作業している現場を見る |
| **ウォークスルー** | 1 つの取引を、最初から最後まで記録をたどって確かめる |
| **CAAT**（コンピュータ支援監査技法） | 監査人がコンピュータを使ってデータを分析する |

監査人は、手続で集めた **監査証拠** に基づいて意見を述べます。証拠がない事柄について推測で指摘はしません。

#### IT に関わる統制

- **IT 全般統制**: システムの開発・変更・運用・アクセス管理など、業務処理の土台になる仕組みの統制
- **IT 業務処理統制**: 個々の業務システムの中で、入力・処理・出力が正しく行われるようにする統制（入力値のチェック、承認など）

参照する基準として、経済産業省の **システム監査基準** と **システム管理基準** があります。

### 4. 経営と財務

#### 投資の評価

| 方法 | 考え方 |
|---|---|
| **回収期間法** | 投資額を何年で回収できるか。短いほどよい |
| **ROI**（投資利益率） | 利益 ÷ 投資額 |
| **NPV**（正味現在価値） | 将来入ってくるお金を **現在の価値に割り引いて** 合計し、投資額を引く。0 より大きければ投資する価値がある |

NPV で割り引くのは、「今の 100 万円」と「1 年後の 100 万円」は価値が違う（今あれば運用して増やせる）からです。割引率 5% なら、1 年後の 105 万円が今の 100 万円と同じ価値、と考えます。

#### 財務指標

| 指標 | 式 | 何が分かるか |
|---|---|---|
| **ROE**（自己資本利益率） | 当期純利益 ÷ 自己資本 | 株主のお金でどれだけ稼いだか |
| **ROA**（総資産利益率） | 利益 ÷ 総資産 | 持っている資産全体でどれだけ稼いだか |
| **流動比率** | 流動資産 ÷ 流動負債 | 1 年以内の支払い能力 |
| **自己資本比率** | 自己資本 ÷ 総資本 | 借金に頼りすぎていないか |

#### 在庫の発注

在庫がこの量まで減ったら注文する、という水準が **発注点** です。

```
発注点 ＝ 1 日あたりの使用量 × 調達期間（日） ＋ 安全在庫
```

**例**: 1 日 20 個使う部品の取り寄せに 5 日かかり、安全在庫を 30 個持つなら、発注点は 20 × 5 ＋ 30 ＝ **130 個**。

### 5. 意思決定とゲーム理論

結果が読めない状況で選択肢を選ぶときの基準です。

| 基準 | 選び方 | 性格 |
|---|---|---|
| **マクシミン原理** | 各選択肢の **最悪の結果** を比べて、その中で最もよいものを選ぶ | 慎重 |
| **マクシマックス原理** | 各選択肢の **最良の結果** を比べて、その中で最もよいものを選ぶ | 楽観的 |
| **期待値原理** | 確率が分かっているなら、期待値が最大のものを選ぶ | 平均で考える |

### 6. 技術経営とビジネスの用語

- **MOT**（技術経営）: 技術を事業の成果につなげるための経営
- **イノベーションのジレンマ**: 優良企業ほど既存の顧客の声に応えるあまり、最初は性能の低い新技術（破壊的イノベーション）に追い越される
- **キャズム**: 新製品が、新しもの好きの人たち（初期採用者）から多数派へ広がる手前にある深い溝
- **デスバレー**: 研究開発の成果が、製品化・事業化される手前で資金や体制が続かずに止まってしまう段階
- **オープンイノベーション**: 社外の技術やアイデアを積極的に取り入れる
- **ビジネスモデルキャンバス**: 顧客・価値提案・収益の流れなど 9 つの要素でビジネスモデルを整理する

### 7. 契約と法律の上乗せ

- **準委任契約** には、作業の量（時間）に対して報酬を払う **履行割合型** と、成果物の完成に対して払う **成果完成型** がある（2020 年の民法改正で整理された）
- **契約不適合責任**: 請負で納めたものが契約の内容に合わないとき、発注者は修理・代金の減額・損害賠償などを求められる（以前の「瑕疵担保責任」に代わる考え方）
- **個人情報保護法**: 漏えいなどで本人の権利を害するおそれが大きいときは、個人情報保護委員会への報告と本人への通知が義務になっている
- **フリーランス法**（2024 年施行）: 個人で仕事を受ける人に対して、発注する事業者が取引条件を書面などで示すことなどを義務づける

## 手を動かすパート

EVM と NPV は、Python で式を書くと理解が早くなります。

```python
>>> bac, pv, ev, ac = 1000, 400, 300, 400
>>> spi, cpi = ev / pv, ev / ac
>>> spi, cpi, bac / cpi
(0.75, 0.75, 1333.3333333333333)
>>> # 3 年間、毎年 40 万円入る投資（初期投資 100 万円、割引率 5%）の NPV
>>> sum(40 / 1.05 ** t for t in (1, 2, 3)) - 100
8.929921174819128
```

## つまずきポイント

> [!CAUTION]
> マネジメント系・ストラテジ系の上乗せ分は **似た略語の取り違え** で落としやすい。略語を見たら日本語の意味に直してから選択肢を読む。

- <mark>**SPI と CPI の分母**</mark>: PV ならスケジュール、AC ならコスト。分子はどちらも EV
- <mark>**RTO と RPO**</mark>: いつまでに再開するか（時間）と、どの時点まで戻すか（データ）
- <mark>**マクシミンとマクシマックス**</mark>: 最悪の中の最善か、最善の中の最善か
- <mark>**NPV は割り引いてから引く**</mark>: 将来の金額をそのまま足すと過大になる
- **IT 全般統制と業務処理統制**: 土台の仕組みか、個々のシステムの中か

## 重要な単語まとめ

| 用語 | 一言で言うと | 身近な実例 |
|---|---|---|
| **SPI / CPI** | EV ÷ PV / EV ÷ AC | 1 未満なら遅れ / 予算超過 |
| **EAC** | 完成時の総コストの見込み | BAC ÷ CPI |
| **EMV** | 発生確率 × 影響額 | 対策費と比べて判断 |
| **可用性管理 / 容量管理 / 継続管理** | 使える状態 / 足りる量 / 災害時の再開 | サーバの増強計画 |
| **RTO / RPO** | 再開までの時間 / 戻せるデータの時点 | 毎晩バックアップなら RPO は最大 1 日 |
| **監査手続 / 監査証拠** | 証拠を集める方法 / 意見の根拠 | インタビュー、突合 |
| **IT 全般統制 / IT 業務処理統制** | 土台の統制 / 個々のシステム内の統制 | アクセス管理 / 入力チェック |
| **NPV / 回収期間法** | 割り引いた正味の価値 / 回収までの年数 | 設備投資の判断 |
| **ROE / 流動比率** | 自己資本あたりの利益 / 短期の支払い能力 | 決算書の分析 |
| **発注点** | 使用量 × 調達期間 ＋ 安全在庫 | コンビニの自動発注 |
| **マクシミン / マクシマックス** | 最悪の中の最善 / 最善の中の最善 | 慎重派と楽観派 |
| **イノベーションのジレンマ / キャズム** | 優良企業が新技術に負ける / 普及の手前の溝 | デジカメとフィルム |
| **準委任（履行割合型・成果完成型）** | 作業量か成果に報酬を払う委任 | SES 契約 |
| **契約不適合責任** | 契約に合わない納品物への責任 | 旧・瑕疵担保責任 |
