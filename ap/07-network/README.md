## 本文

### 1. 問題の形

ある会社のネットワーク構成図（拠点、ルータ、L2/L3 スイッチ、ファイアウォール、サーバ、無線 LAN）と、機器の設定表（IP アドレス、VLAN、ルーティングの表）が示され、次のようなことを問われます。

- 構成図の中の機器の **役割** や **空欄の用語**
- ある端末からあるサーバへの **通信がどこを通るか**
- 設定表の **誤り** と、そのとき起きる現象
- 新しい要件（拠点の追加、冗長化、在宅勤務）に対する **設定の変更**

### 2. 構成図を「パケットの旅」として読む

> [!CAUTION]
> <mark>**通信の流れの設問は、送信元から宛先まで、パケットがどの機器を順に通るかを図に指で書いて追う**</mark>。途中で、宛先の IP アドレスを決める（DNS）、出口を決める（ルーティング）、アドレスを書き換える（NAT・プロキシ）、通すか決める（ファイアウォール）のどれが起きるかを 1 つずつ確かめる。頭の中だけで追うと、どこかを飛ばす。

**例**: 社内の PC がブラウザで外部の Web サイトを見るとき

1. PC が DNS サーバに名前を問い合わせ、IP アドレスを得る（Web 編 Ch2）
2. PC はプロキシサーバに接続する（ブラウザの設定でプロキシを使う場合）
3. プロキシサーバが、代わりに外部の Web サーバに接続する
4. ファイアウォールが、プロキシサーバからの HTTPS の通信だけを許可している
5. ルータで NAPT により、送信元が会社のグローバル IP アドレスに変換される

この流れのどこかの設定が欠けると、「名前は引けるのにつながらない」「特定の端末だけつながらない」といった現象になります。

### 3. IP アドレスの設計

**例題**: ある拠点に、PC 100 台、プリンタ 10 台、サーバ 5 台を置き、ルータのアドレスも 1 つ必要。1 つのサブネットにまとめるとき、最も小さいサブネットのプレフィックス長は？

1. 必要なアドレス数: 100 ＋ 10 ＋ 5 ＋ 1 ＝ 116
2. ホスト部が n ビットのとき、使えるアドレスは 2ⁿ − 2。2⁷ − 2 ＝ 126 ≧ 116 なので n ＝ 7
3. プレフィックス長は 32 − 7 ＝ **/25**

将来の増加を考えて 1 段大きめにする、という条件が本文にあれば、それに従います。

### 4. VLAN とルーティング

- **VLAN**: 1 台のスイッチを、設定で複数の独立した LAN に分ける。部署ごとに分けると、ほかの部署への不要な通信（ブロードキャスト）が届かなくなる
- **タグ VLAN**（IEEE 802.1Q）: 1 本のケーブルで複数の VLAN の通信を運ぶために、フレームに VLAN 番号の目印（タグ）を付ける
- **VLAN 間の通信**: VLAN が違えば別のネットワークなので、ルータか **L3 スイッチ** で中継する必要がある
- **静的ルーティングと動的ルーティング**: 経路を手で設定するか、ルータどうしが情報を交換して自動で決めるか（OSPF など）
- **デフォルトルート**: どの経路にも当てはまらない宛先の通信を送る先（`0.0.0.0/0`）

### 5. 冗長化

| 仕組み | 中身 |
|---|---|
| **VRRP** | 2 台のルータで 1 つの仮想 IP アドレスを共有し、主のルータが止まると副が引き継ぐ。端末のデフォルトゲートウェイは仮想 IP アドレスにしておく |
| **リンクアグリゲーション** | 複数の回線を束ねて 1 本として扱う。帯域が増え、1 本切れても通信が続く |
| **スパニングツリー** | スイッチをループ状につないだとき、通信が永遠に回り続ける（ブロードキャストストーム）のを防ぐため、一部の経路を自動で止めておく |
| **回線の二重化** | 通信事業者を 2 社にするなど |

### 6. 無線 LAN と認証

- **IEEE 802.1X**: ネットワークにつなぐ前に、利用者や端末を認証する仕組み。認証サーバ（RADIUS）と組み合わせる。電子証明書で端末を認証すると、許可していない私物の端末をつながせない
- **WPA3**: 無線 LAN の暗号化。会社では個人ごとの認証ができる WPA3-Enterprise（802.1X と組み合わせる）を使う
- **ローミング**: 移動して別のアクセスポイントにつなぎ替わること

**実例**: 大学の Wi-Fi で、学籍番号とパスワードを入れて接続するのは、IEEE 802.1X による認証です。カフェの Wi-Fi のように全員が同じパスワードを使う方式（WPA3-Personal）とは違います。

### 7. ロードバランサ

- **ヘルスチェック**: 振り分け先のサーバが正常かを定期的に確かめ、異常なサーバには振り分けない。ポートに接続できるかだけを見る方法と、実際にページを取得して中身を確かめる方法がある
- **セッション維持**（パーシステンス）: 同じ利用者の通信を同じサーバに振り分ける。ログイン状態をサーバのメモリに持っている場合に必要（Web 編 Ch3 の Cookie とセッション）。Cookie の値や送信元 IP アドレスで判定する
- **TLS の終端**: ロードバランサで HTTPS を復号し、その先のサーバとは HTTP で通信する（Web 編 Ch7 の Nginx と同じ考え方）

## 手を動かすパート

サブネットの設計は Python の `ipaddress` で確かめられます。

```python
>>> import ipaddress
>>> need = 100 + 10 + 5 + 1
>>> prefix = next(p for p in range(30, 0, -1) if 2 ** (32 - p) - 2 >= need)
>>> prefix
25
>>> list(ipaddress.ip_network("10.1.0.0/24").subnets(new_prefix=25))
[IPv4Network('10.1.0.0/25'), IPv4Network('10.1.0.128/25')]
```

## つまずきポイント

> [!CAUTION]
> ネットワークの記述は **「どの機器の、どの設定が」** まで具体的に書かないと点にならない。「ネットワークの設定を見直す」のような答えは避ける。

- <mark>**VLAN 間は L3 で中継が必要**</mark>: 同じスイッチにつながっていても、VLAN が違えば直接は通信できない
- <mark>**VRRP のときのデフォルトゲートウェイ**</mark>: 個々のルータの実 IP アドレスではなく、仮想 IP アドレスにする
- <mark>**アドレス数の計算は − 2 とルータの分**</mark>: 割り当てられないアドレスと、ゲートウェイの分を忘れない
- <mark>**ヘルスチェックの深さ**</mark>: ポートが開いていても、アプリが壊れていることがある
- **セッション維持が要る理由**: サーバ側でセッションを持っているから

## 重要な単語まとめ

| 用語 | 一言で言うと | 身近な実例 |
|---|---|---|
| **プレフィックス長の設計** | 必要なアドレス数から /n を決める | 116 台なら /25 |

| **L3 スイッチ** | ルーティングもできるスイッチ | VLAN 間の中継 |

| **リンクアグリゲーション** | 複数の回線を束ねる | 帯域増と冗長化 |

| **ヘルスチェック** | 振り分け先が正常かの定期確認 | 壊れたサーバを外す |
