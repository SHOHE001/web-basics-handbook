## 本文

### 1. システムアーキテクチャの問題の形

ある会社のシステム構成（Web サーバ・AP サーバ・DB サーバ、クラウドかオンプレミスか）と、利用状況や要件（ピーク時のアクセス数、応答時間の目標、稼働率の目標）が示され、次のような点が問われます。

- ピーク時に必要な **サーバの台数** や **CPU の使用率**
- 冗長構成にしたときの **稼働率**
- 障害が起きたときに **何が止まるか**、どこが単一障害点になるか
- 要件を満たすための **構成の変更案**

### 2. 性能の見積り

**例題**: 1 件の処理に CPU 時間を 40 ミリ秒使う。ピーク時に毎秒 60 件の要求が来る。CPU 使用率を 70% 以下に抑えるには、1 コアのサーバが何台必要か。

1. 1 秒あたりに必要な CPU 時間: 60 × 0.04 ＝ 2.4 秒
2. 1 台あたり 70% まで使えるので、1 台につき 0.7 秒分を処理できる
3. 2.4 ÷ 0.7 ≒ 3.43 → **4 台**（切り上げる）

> [!CAUTION]
> <mark>**台数の計算は必ず切り上げる**</mark>。3.43 台となった場合、3 台では足りない。さらに「1 台が故障しても要件を満たす」と書かれていれば、もう 1 台足す必要がある（N ＋ 1 構成）。本文の条件を 1 つでも読み落とすと答えがずれてしまう。

### 3. 単一障害点と冗長化

**単一障害点**（SPOF）とは、そこが 1 か所止まるだけでシステム全体が停止してしまう部分のことです。Web サーバを 3 台に増やしても、その手前に置いたロードバランサが 1 台だけなら、そこが単一障害点になります。

| 構成 | 中身 |
|---|---|
| **アクティブ／スタンバイ** | 1 台が処理を行い、もう 1 台は待機する。切替えに時間がかかることがある |
| **アクティブ／アクティブ** | 両方が処理を行う。1 台が止まると残りの 1 台に負荷が集中するため、1 台で全体の負荷を受け止められる性能が必要 |
| **クラスタ** | 複数台で 1 つのサービスを提供し、故障した機器を自動的に切り離す |

稼働率の計算は、FE Chapter 5 で扱った直列・並列の組合せと同じです。AP では、構成図から直列部分と並列部分を自分で読み取る必要があるため、難易度が一段上がります。

### 4. クラウドの構成

- **オートスケール**: 負荷に応じてサーバの台数を自動で増減させる仕組み。台数を増やすのに数分かかるため、急激なアクセスの増加には間に合わないことがある
- **マネージドサービス**: DB などの運用をクラウド事業者に任せるサービス。障害時の切替えやバックアップを任せられる
- **リージョンとアベイラビリティゾーン**: リージョンは地域（東京、大阪など）、ゾーンはその中にある独立したデータセンター群を指す。ゾーンをまたいで配置すれば、1 つのデータセンターで障害が起きても耐えられる
- **責任共有モデル**: クラウド事業者が守る範囲（設備・基盤）と、利用者が守る範囲（OS の設定・データ・アクセス権）の役割分担

### 5. バックアップと災害対策

| 方式 | 中身 |
|---|---|
| **コールドサイト** | 設備だけを用意しておき、災害時に機器とデータを持ち込む。費用は安いが復旧は遅い |
| **ウォームサイト** | 機器はあらかじめ用意しておき、データは定期的に送る |
| **ホットサイト** | 本番と同じ構成を常に稼働させ、データも同期しておく。費用は高いが復旧は速い |

どの方式を選ぶかは、AP Chapter 2 で学んだ **RTO**（いつまでに再開するか）と **RPO**（どの時点のデータまで戻すか）によって決まります。

### 6. 組込みシステム開発の問題の形

家電・自動車・ロボット・センサー機器といった組込みシステムについて、ハードウェアの構成やソフトウェアのタスク一覧、状態遷移表などが示されます。

**実例**: ロボット掃除機は、センサー（バンパー、段差センサー、カメラ）で周囲を測定してモーター（アクチュエータ）を動かし、バッテリー残量が減ったら充電台に戻るという状態の移り変わりを持つ組込みシステムです。

### 7. リアルタイム処理とタスク

- **リアルタイム OS**（RTOS）: 決められた時間内に処理を終えることを重視した OS
- **タスクの優先度**: 優先度の高いタスクが実行可能になると、実行中の優先度が低いタスクを中断して先に実行する仕組み（**プリエンプション**）
- **割込み**: ボタンが押された、センサーが値を出力した、タイマが指定時間になった、といったきっかけで、実行中の処理を中断して割込み処理を動かす仕組み
- **優先度逆転**: 優先度の低いタスクが保持している資源を優先度の高いタスクが待っている間に、中程度の優先度のタスクが割り込むことで、優先度の高いタスクがいつまでも動けなくなる現象

> [!CAUTION]
> 組込みの設問では、<mark>**タスクの優先度と実行順序をタイムライン（時間軸）に書いて追う**</mark> のが確実である。「優先度の高いタスクが発生したら、低いタスクは途中で止まる」という動きを図にしないと、どのタスクがいつ終わるかを読み違えてしまう。

### 8. 状態遷移表

組込みシステムの動きは、状態とイベントを組み合わせた表で表されることがよくあります。

| 現在の状態 ＼ イベント | 開始ボタン | 段差を検知 | 残量 20% 未満 |
|---|---|---|---|
| 待機中 | 掃除中へ | ― | 充電へ |
| 掃除中 | 待機中へ | 後退して方向転換 | 帰還中へ |
| 帰還中 | ― | 後退して方向転換 | ― |

設問では、表の空欄に入る遷移先を埋めたり、「ある条件で想定外の状態に陥る不具合」の原因を表から探したりします。

### 9. タイマとセンサーの計算

- **タイマ割込みの周期**: 例えばカウンタが 1 MHz（毎秒 100 万回）でカウントし、1,000 回ごとに割込みを発生させるなら、割込みは 1 ミリ秒ごとに起きる
- **A/D 変換**: センサーのアナログ値をデジタル値に変換する処理。10 ビットの変換器で 0〜5 V を測定するなら、1 段階あたり 5 ÷ 1,024 ≒ 4.9 mV となる
- **処理時間の積み上げ**: 1 周期の中で、各タスクの処理時間の合計が周期を超えないかを確認する

## 手を動かすパート

性能の見積りでは、条件を変数にしておくと検算が楽になります。

```python
>>> import math
>>> requests_per_sec, cpu_sec_per_req, max_util = 60, 0.04, 0.7
>>> math.ceil(requests_per_sec * cpu_sec_per_req / max_util)        # 必要な台数
4
>>> math.ceil(requests_per_sec * cpu_sec_per_req / max_util) + 1    # 1 台故障しても大丈夫な台数
5
```

## つまずきポイント

> [!CAUTION]
> この 2 分野では、**本文の数値と条件の読み落とし** がそのまま失点につながる。計算に入る前に、使う数値に線を引いて単位をそろえておくこと。

- <mark>**台数は切り上げ、故障時の条件があれば ＋1 する**</mark>
- <mark>**単一障害点を見落とさない**</mark>: 台数を増やしたサーバの前後にある、1 台だけの機器に注意する
- <mark>**アクティブ／アクティブの落とし穴**</mark>: 1 台が故障した際、残りの機器にすべての負荷がかかる
- **優先度逆転**: 「優先度が高いのに動けない」原因として問われる
- **状態遷移表の「―」**: 「何もしない」のか「想定していない」のかを本文で確かめる

## 重要な単語まとめ

| 用語 | 一言で言うと | 身近な実例 |
|---|---|---|
| **CPU 使用率の見積り** | 必要な CPU 時間 ÷ 使える CPU 時間 | ピーク時のサーバ台数 |
| **N ＋ 1 構成** | 必要台数に予備を 1 台足す構成 | 1 台故障しても稼働し続ける |
| **単一障害点（SPOF）** | そこが止まると全体が止まる部分 | 1 台だけのロードバランサ |
| **アクティブ／スタンバイ・アクティブ／アクティブ** | 待機させる方式 / 両方動かす方式 | DB の冗長化 |
| **オートスケール** | 負荷に応じて台数を自動で増減させる仕組み | セール時のアクセス増加への対応 |
| **アベイラビリティゾーン** | リージョン内の独立したデータセンター群 | ゾーンをまたいで配置する |
| **責任共有モデル** | クラウド事業者と利用者の責任分担 | OS の設定は利用者の責任 |
| **ホット／ウォーム／コールドサイト** | 災害対策における準備の度合い | RTO・RPO に応じて選ぶ |
| **リアルタイム OS / プリエンプション** | 時間内の処理を保証 / 優先タスクによる中断 | 自動車のブレーキ制御 |
| **優先度逆転** | 優先度の高いタスクが低いタスクに間接的に待たされる現象 | 資源の取り合い |
| **状態遷移表** | 状態 × イベントで次の状態を表す表 | ロボット掃除機の動き |
| **A/D 変換** | アナログ値をデジタル値に変換する処理 | センサーの読み取り |
