## 本文

### 1. 経営戦略の問題の形

ある会社の事業の状況（市場、競合、自社の強みと弱み、業績の数字）と、検討している施策（新事業、DX、IT 投資）が示され、次のようなことが問われます。

- SWOT・PPM・バリューチェーンなどの **分析手法を本文に当てはめた結果**
- 施策の **狙い** や、それによって解決する **課題**
- 売上・利益・投資回収などの **計算**
- 施策を成功させるための **KPI** の設定

### 2. 分析手法を本文に当てはめる

> [!CAUTION]
> SWOT 分析の設問では、<mark>**強み・弱みは「自社の内部」、機会・脅威は「外部の環境」**</mark> という区別で本文の記述を振り分ける。「競合が値下げした」は自社の弱みではなく外部の脅威であり、「熟練の職人が多い」は内部の強みである。主語が自社か、市場・競合・社会かで判断する。

その他の手法の当てはめ方:

- **PPM**: 本文の「市場の伸び」と「自社のシェア」という 2 つの情報から、事業を花形・金のなる木・問題児・負け犬に分類する（FE Chapter 11）
- **バリューチェーン**: 会社の活動を、価値を生む流れ（購買物流 → 製造 → 出荷物流 → 販売 → サービス）と支援活動（人事・技術開発・調達など）に分けて、どこで差を付けているかを見る
- **アンゾフの成長マトリクス**: 製品（既存・新規）× 市場（既存・新規）の組み合わせで、市場浸透・新市場開拓・新製品開発・多角化の 4 つに分類する
- **BSC**: 財務・顧客・業務プロセス・学習と成長の 4 つの視点で、目標と KPI を因果関係のつながりに沿って並べる

### 3. 財務の計算

**例題**: 新しいサービスの固定費が年 1,200 万円、1 件あたりの売上が 5,000 円、1 件あたりの変動費が 2,000 円である。年に何件売れば黒字になるか。

1. 1 件あたりの **限界利益**（売上 − 変動費）: 5,000 − 2,000 ＝ 3,000 円
2. 固定費を回収するのに必要な件数: 1,200 万 ÷ 3,000 ＝ 4,000 件
3. **4,000 件を超えれば黒字**

これは FE Chapter 11 の損益分岐点を「件数」で考えたものです（変動費率は 0.4 で、損益分岐点売上高は 1,200 万 ÷ 0.6 ＝ 2,000 万円 ＝ 4,000 件分）。

#### KPI の設定

<mark>**KPI は、施策の狙いに直接つながり、数値で測れるものにします**</mark>。「顧客満足度を高める」は目標であって KPI ではありません。「アプリ経由の再来店率を 30% にする」のように、何をいつまでにどれだけ達成するかを数字で書きます。

### 4. システム監査の問題の形

ある会社のシステムや業務（販売管理、アクセス権の管理、外部委託の管理など）の状況と、監査人が行った予備調査の結果が示され、システム監査人の立場で次のようなことが問われます。

- 確かめるべき **リスク** と、そのために見る **監査証拠**
- 適切な **監査手続**
- 本文の状況から読み取れる **不備の指摘**
- 不備に対する **改善提案**

### 5. 監査証拠と監査手続

設問は「〜を確かめるために、監査人は何を確認すべきか」という形が多く、答えは **具体的な記録や資料** になります。

| 確かめたいこと | 見る証拠（例） |
|---|---|
| アクセス権が適切に管理されているか | 権限の申請書・承認記録と、システムに登録された権限の一覧を **突合** する |
| 退職者のアカウントが削除されているか | 人事の退職者一覧と、システムのアカウント一覧を突合する |
| プログラムの変更が承認されているか | 変更の申請・承認記録と、本番環境への反映記録を突合する |
| バックアップから復元できるか | 復元テストの実施記録 |
| 委託先の管理が適切か | 委託契約書、委託先からの報告書、立入り調査の記録 |

> [!CAUTION]
> 監査人は <mark>**自分で業務を行ったり、システムを直したりしない**</mark>。答えが「監査人がアカウントを削除する」「監査人が手順書を作る」になっていたら誤りである。監査人が行うのは、証拠を見て評価し、改善を **提案** することである。改善を実施するのは対象の部門である。

### 6. 指摘と改善提案の書き方

- **指摘**: 本文の事実に基づいて、「何が」「どの基準に照らして」不十分かを書く。例：「権限の変更が申請書なしで行われており、承認の記録が残っていない」
- **改善提案**: 指摘した不備の原因を取り除く仕組みを書く。例：「権限の変更は申請と上長の承認を必須とし、承認記録と登録内容を定期的に照合する」
- **予防と発見**: 不正やミスを起こさせない統制（承認、職務の分離）と、起きたときに気付く統制（定期的な照合、ログの点検）の両方を考える

**実例**: アルバイト先のレジ締めで、売上の記録と現金を 2 人で数え合わせるのは、発見的な統制の身近な例です。1 人がレジ打ちと現金管理の両方を担当しないようにするのは、職務の分離（予防的な統制）です。

## 手を動かすパート

限界利益と損益分岐点は、式にして確かめられます。

```python
>>> fixed, price, variable = 12_000_000, 5_000, 2_000
>>> fixed / (price - variable)                      # 損益分岐点の件数
4000.0
>>> fixed / (1 - variable / price)                  # 損益分岐点の売上高
20000000.0
```

## つまずきポイント

> [!CAUTION]
> この 2 分野は **立場の取り違え** で点を落としやすい。経営戦略は経営者・企画担当者、監査は独立した監査人の立場で答える。

- <mark>**SWOT の内部と外部**</mark>: 主語が自社なら強み・弱み、外部環境なら機会・脅威
- <mark>**KPI は数えられるものに**</mark>: 「高める」ではなく具体的な数字と期限で示す
- **監査人は実施しない**: 改善を提案するまでが役割
- **証拠は具体的な記録で**: 「関係者に確認する」より「承認記録と権限一覧を突合する」
- **予防的統制と発見的統制**: 両方をそろえた提案が説得力を持つ

## 重要な単語まとめ

| 用語 | 一言で言うと | 身近な実例 |
|---|---|---|
| **SWOT（内部・外部）** | 強み・弱みは自社、機会・脅威は環境 | 競合の値下げは脅威 |
| **バリューチェーン** | 価値を生む活動の流れの分析 | どこで差を付けているか |
| **アンゾフの成長マトリクス** | 製品 × 市場の新旧で分ける 4 つの戦略 | 既存商品を新しい国で売るのは新市場開拓 |
| **限界利益** | 売上 − 変動費 | 1 件 3,000 円 |
| **KPI** | 数えられる途中経過の指標 | 再来店率 30% |
| **監査証拠 / 突合** | 意見の根拠 / 2 つの記録を照らし合わせる | 権限申請と権限一覧 |
| **指摘 / 改善提案** | 事実に基づく不備 / 原因を取り除く仕組み | 承認の必須化 |
| **予防的統制 / 発見的統制** | 起こさせない / 起きたら気付く | 職務の分離 / 定期照合 |
| **職務の分離** | 1 人に権限を集中させない | レジ打ちと現金管理を分ける |
