## 本文

### 1. 問題の形式

プログラミングの問題は、FE の科目 B と同じ **擬似言語** で書かれたプログラムと、その説明文で構成されています。FE との違いは次のとおりです。

| | FE 科目 B | AP 科目 B（問 3） |
|---|---|---|
| 長さ | 1 問につき 1 プログラムで、短い | 1 問に複数の関数があり、説明文も長い |
| 答え方 | 選択肢から選ぶ | 空欄の式や字句を **自分で書く**、数値を答える、計算量を答える |
| 題材 | 基本的な探索・整列・配列の操作 | 動的計画法、グラフ、木、文字列照合など、一段複雑なもの |

<mark>**選択肢がないため、「それらしい式」を当てはめて確かめることができません**</mark>。自分でトレースして、式が正しいことを確かめる力が必要です。

### 2. 動的計画法

大きな問題を小さな部分問題に分け、**部分問題の答えを表に記録して使い回す** 方法です。同じ計算を何度も繰り返さないため、処理が速くなります。

**例**: フィボナッチ数（1, 1, 2, 3, 5, 8, …）を素直な再帰で計算すると、同じ値を何度も計算することになり、n が増えると計算回数が爆発的に増加します。

```
fib(5) ＝ fib(4) ＋ fib(3)
       ＝ (fib(3) ＋ fib(2)) ＋ (fib(2) ＋ fib(1))   ← fib(3) や fib(2) を何度も計算
```

表 `memo` に一度計算した値を記録しておけば、各値を 1 回ずつ計算するだけで済みます（O(n)）。

#### ナップサック問題

「重さの上限がある袋に、価値の合計が最大になるように品物を詰める」という問題は、動的計画法の定番です。`best[w]` に「重さの上限が w のときの最大の価値」を記録し、品物を 1 つずつ検討しながら表を更新していきます。

```
for 各品物 (重さ wi, 価値 vi)
  for (w を 上限 から wi まで 1 ずつ減らす)     // 大きい方から更新するのがポイント
    best[w] ← max(best[w], best[w − wi] ＋ vi)
  endfor
endfor
```

> [!CAUTION]
> 上の表の更新において、<mark>**w を大きい方から小さい方へ回すのは、同じ品物を 2 回使わないようにするためである**</mark>。小さい方から回すと、直前に更新したばかりの `best[w − wi]`（すでにこの品物を入れた値）を使ってしまい、同じ品物を何個でも入れられる別の問題になってしまう。ループの向きを問う空欄は、この理由から決まる。

### 3. グラフの最短経路（ダイクストラ法）

辺に距離（重み）が付いたグラフにおいて、出発点から各点までの最短距離を求める方法です。重みが負でないことが前提となります。

1. 出発点の距離を 0、それ以外の点の距離を無限大にする
2. まだ確定していない点のうち、距離が最小の点を選んで **確定** する
3. 確定した点から出る辺をたどり、隣の点の距離が現在より短くなるなら更新する
4. すべての点が確定するまで 2〜3 を繰り返す

**実例**: 乗換案内アプリや地図アプリの経路検索は、この考え方を土台として、さらに高速化する工夫を加えたものです。

### 4. 木の操作

- **2 分探索木への挿入**: 根から始めて、挿入する値が小さければ左、大きければ右へと進み、空いている場所に配置する
- **ヒープ**: 配列で表すとき、要素番号が 1 から始まる場合、要素番号 i の子は 2i と 2i ＋ 1、親は i ÷ 2（切り捨て）となる。値を追加したら、親と大小を比べて入れ替えながら上へと移動させる
- **木の高さと計算量**: バランスの取れた 2 分探索木であれば探索は O(log n) となる。値を小さい順に挿入すると一直線の木になり、計算量は O(n) に低下する

### 5. 文字列の照合

長い文章（テキスト）の中から、特定のパターンの文字列を探す問題です。

- **素朴な方法**: テキストの各位置から、パターンと 1 文字ずつ比較する。計算量は最悪で O(テキストの長さ × パターンの長さ) となる
- **BM 法（ボイヤー・ムーア法）**: パターンの **末尾から** 比較し、一致しなかった文字に応じて、パターンを一気に何文字もずらす。ずらす量は、パターンをもとにあらかじめ表にしておく

設問では、「ずらす量の表」の値を答えさせたり、比較の回数を数えさせたりします。

### 6. 空欄補充の解き方（FE からの上乗せ）

1. **変数の意味を日本語で書き出す**: 「`left` は探索範囲の左端」「`count` はここまでに見つかった個数」など
2. **ループの前後で何が成り立つかを考える**: 「ループの i 回目の終わりには、配列の 1〜i 番目が整列済みである」のように、毎回成り立つ性質（**ループ不変条件**）を見つけると、空欄の式が決まりやすい
3. **境界を試す**: 要素数が 0、1、2 のときに、ループが正しく回るか、また正しく止まるかを確認する
4. **計算量を問われたら**: ループの入れ子の深さと、1 回あたりに探索範囲が半分になるか（log）に着目する

## つまずきポイント

> [!CAUTION]
> AP のプログラミング問題は **ループの境界と向き** で失点することが多い。空欄を埋めたら、小さい例で 1 回はトレースする。

- <mark>**ナップサックのループの向き**</mark>: 品物が 1 個ずつなら上限から小さい方へ回す
- <mark>**ダイクストラ法は負の重みでは使えない**</mark>: 確定した距離が後から縮むことがあるため
- <mark>**ヒープの添字**</mark>: 要素番号が 0 から始まるときは、子が 2i ＋ 1 と 2i ＋ 2 になる
- **2 分探索木の最悪ケース**: 整列済みの順に入れると一直線の木になる
- **メモ化の初期値**: 「まだ計算していない」ことを表す値（未定義や −1）と、計算結果の 0 を区別する
