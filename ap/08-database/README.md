## 本文

### 1. 問題の形

ある業務（図書館の貸出、ネット通販の受注、イベントの予約など）の説明と、その業務のデータの E-R 図、表の定義、SQL 文が示され、次のようなことを問われます。

- E-R 図の **空欄のエンティティや多重度**
- 業務の要件を満たす **SQL の空欄**
- ある SQL の **実行結果**
- 要件の変更に合わせた **表の変更**
- 同時に更新したときの **不整合** とその対策

### 2. E-R 図と多重度

関連の線の端に、相手側がいくつ対応するかを書きます（表記は問題文の凡例に従います）。

| 多重度 | 意味 | 例 |
|---|---|---|
| 1 対 1 | 互いに 1 つずつ | 社員 ― 社員証 |
| 1 対多 | 片方 1 つに、もう片方が複数 | 会員 ― 貸出記録 |
| 多対多 | 互いに複数 | 学生 ― 講義（履修） |

多対多は、そのままでは表にできないので、間に **連関エンティティ**（履修表など）を置いて 1 対多 ＋ 多対 1 に分けます。

<mark>**1 対多の関連は、「多」の側の表に「1」の側の主キーを外部キーとして持たせる**</mark>。貸出記録の表に会員番号の列があるのはこのため。E-R 図から表の定義の空欄を埋める設問は、ほぼこの規則で解けます。

### 3. 一段上の SQL

#### 外部結合

FE で見た `JOIN`（内部結合）は、両方の表に対応する行があるものだけを残します。**左外部結合**（`LEFT OUTER JOIN`）は、左の表の行を **すべて残し**、右に対応する行がなければ右の列を NULL にします。

```sql
-- 一度も貸出のない会員も含めて、会員ごとの貸出件数を出す
SELECT 会員.会員番号, COUNT(貸出.貸出番号) AS 件数
FROM 会員
LEFT OUTER JOIN 貸出 ON 会員.会員番号 = 貸出.会員番号
GROUP BY 会員.会員番号;
```

> [!CAUTION]
> 外部結合で件数を数えるときは <mark>**`COUNT(*)` ではなく `COUNT(右の表の列)`**</mark> にする。`COUNT(*)` は NULL だけの行も 1 件と数えるので、貸出が 0 件の会員が「1 件」になってしまう。`COUNT(列)` は NULL を数えない。この違いを問う空欄は定番。

#### EXISTS

副問合せが 1 行でも返すかどうかで条件を判定します。

```sql
-- 返却期限を過ぎて未返却の本がある会員
SELECT 会員番号, 氏名 FROM 会員
WHERE EXISTS (
  SELECT * FROM 貸出
  WHERE 貸出.会員番号 = 会員.会員番号      -- 外の行を参照する（相関副問合せ）
    AND 貸出.返却日 IS NULL
    AND 貸出.返却期限 < '2026-11-04'
);
```

`NOT EXISTS` にすると「そういう行が 1 つもない」会員になります。

#### CASE

値によって出力を変えます。

```sql
SELECT 書名,
  CASE WHEN 貸出回数 >= 10 THEN '人気' ELSE '通常' END AS 区分
FROM 書籍;
```

#### ウィンドウ関数

行をまとめずに、グループごとの順位や合計を各行に付けます。

```sql
-- ジャンルごとの貸出回数の順位
SELECT ジャンル, 書名, 貸出回数,
  RANK() OVER (PARTITION BY ジャンル ORDER BY 貸出回数 DESC) AS 順位
FROM 書籍;
```

`GROUP BY` は行を 1 行にまとめてしまいますが、ウィンドウ関数は元の行を残したまま集計結果を横に並べられます。

### 4. 同時実行と排他制御

**例**: 在庫が 1 冊の本に、2 人がほぼ同時に貸出を申し込んだ。

| 時刻 | トランザクション A | トランザクション B |
|---|---|---|
| 1 | 在庫を読む（1 冊） | |
| 2 | | 在庫を読む（1 冊） |
| 3 | 在庫を 0 にして貸出を登録 | |
| 4 | | 在庫を 0 にして貸出を登録 |

両方の貸出が成立してしまいます（ロストアップデートの一種）。対策は、読むときから **専有ロック** をかける（`SELECT ... FOR UPDATE` など）か、更新時に「在庫が 1 以上なら減らす」という条件付きの更新（`UPDATE ... SET 在庫 = 在庫 − 1 WHERE 在庫 >= 1`）にして、更新できた件数で成否を判定することです。

**デッドロック** の設問では、2 つのトランザクションが **逆の順番で** ロックを取ろうとしていることを見つけます。対策は「ロックを取る順番をすべてのトランザクションでそろえる」が定番の答えです。

### 5. インデックスと性能

- **インデックス**: 本の索引のように、列の値から行の場所をすぐ引けるようにしたもの。検索は速くなるが、追加・更新のたびにインデックスも更新するので書き込みは遅くなる
- **効きやすい列**: `WHERE` や `JOIN` の条件によく使い、値の種類が多い列（会員番号など）
- **効きにくい場合**: 値の種類が少ない列（性別など）、列に関数をかけた条件、`LIKE '%語'` のような前方が決まらない検索

**実例**: Web 編 Ch6 の SQL インジェクション対策で使ったプレースホルダは、性能面でも、同じ形の SQL を DB が使い回せるという利点があります。

## つまずきポイント

> [!CAUTION]
> データベースの問題は **NULL の扱い** と **結合の種類** で結果が変わる設問が多い。実行結果を答えるときは、小さな表を書いて 1 行ずつ確かめる。

- <mark>**外部結合の件数は `COUNT(列)`**</mark>: `COUNT(*)` は NULL の行も数える
- <mark>**1 対多の外部キーは「多」の側**</mark>
- <mark>**`NOT IN` と NULL**</mark>: 副問合せの結果に NULL が含まれると、`NOT IN` は 1 行も返さなくなる。`NOT EXISTS` の方が安全
- **`WHERE` で右の表の列を条件にすると内部結合と同じになる**: 外部結合で残した NULL の行が、`WHERE 右.列 = ...` で消えてしまう
- **デッドロックの対策**: ロックの順番をそろえる

## 重要な単語まとめ

| 用語 | 一言で言うと | 身近な実例 |
|---|---|---|
| **多重度** | 関連の相手がいくつ対応するか | 会員 1 ― 貸出 多 |
| **連関エンティティ** | 多対多を分けるための間の表 | 履修表 |
| **左外部結合** | 左の表の行を全部残す結合 | 貸出 0 件の会員も表示 |
| **`COUNT(*)` と `COUNT(列)`** | 全行を数える / NULL を除いて数える | 外部結合後の件数 |
| **EXISTS / 相関副問合せ** | 該当行があるか / 外の行を参照する副問合せ | 延滞中の会員 |
| **CASE** | 値によって出力を変える | 「人気」「通常」の区分 |
| **ウィンドウ関数** | 行を残したまま順位や集計を付ける | ジャンル別ランキング |
| **条件付き更新** | 条件を満たすときだけ更新し、件数で判定 | 在庫の二重引当て防止 |
| **インデックス** | 列の値から行を素早く引く索引 | 会員番号での検索 |
